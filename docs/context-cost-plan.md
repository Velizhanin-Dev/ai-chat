# Контекст-архитектура и юнит-экономика чата

> Создано 2026-06-15. План снижения стоимости запроса при сохранении качества «голоса
> Велижанина». Связано с пунктом 3 дорожной карты в [CLAUDE.md](../CLAUDE.md) («Квоты /
> лимиты»). По мере реализации — обновлять статусы фаз внизу файла.

## Цель

Средний чек **3–6¢ за запрос**. Сейчас (Sonnet 4.6, вся база в каждом запросе) — пол
**~5.8¢ только на чтение базы**, а на Opus 4.8 при той же схеме — **~9.5¢**. Без
перестройки контекста подписка 500–1000 ₽/мес не отбивается.

## Что подтверждено фактами

- Реальный лог прод-формата: `cache_read=189984 cache_create=8 input=7 output=60`.
  - Кэш **работает идеально** (запись ≈ 0, чтение 190k). Протухание/TTL — НЕ проблема.
  - Проблема — **фиксированный пол ~190k токенов в каждом запросе**. Даже «прив» стоит
    ~5.8¢ на Sonnet, потому что заново читается вся база.
  - 189 984 — это **99.99% до порога 200K**, за которым у Sonnet включается длинно-
    контекстный премиум (вход 2×). С историей сообщений — переваливаем.
- **Opus 4.8** — единственная модель, что держит роль (Sonnet/Haiku сваливаются в
  «гптшный» тон на длинной генерации). Цена: вход $5/M, выход $25/M, кэш-чтение $0.50/M.
  **У Opus 4.8 НЕТ длинно-контекстного премиума** (1M по стандартной цене) — порог 200K
  перестаёт быть проблемой после перехода на Opus.

## Принцип: стиль ≠ контент

Главная причина, почему RAG раньше звучал «по-гптшному»: через ретрив прогонялось ВСЁ,
включая стиль. Но «как говорить» — не топик, его нельзя достать одним куском. Отсюда
разделение на две полки:

### Полка 1 — «персона-хребет» (грузим ВСЕГДА, кэшируется, ~18k токенов)

- system-промпт (железное правило роли)
- `VOICE_SAMPLES` — якорь интонации
- `ANTIPATTERNS` — правила «не будь ГПТ» (критичнее voice; ретривить НЕЛЬЗЯ)

Это и есть ответ на Задачу 1 (голос). Хребет всегда в контексте → роль держится без
всякого retrieval.

### Полка 2 — «библиотека-фактура» (подгружаем по роутингу)

- `VIDEO_FORMATS` — короткие видео (статичный блок, кэшируется)
- TG закрытый / открытый — короткие видео, кейсы (грузить **только нужный канал**)
- Книга — длинные сценарии, **только через поиск** (единственный слой, что не влезает
  целиком: ~120k токенов)

**Роутер** — дешёвый вызов Haiku: классифицирует запрос
(`болтовня | короткий сценарий | длинный сценарий | формат | общий`) и решает, какие
слои подключить. Голос в классификации не нужен → Haiku, доли цента.

### Задача 2 — дословность сценариев из книги/TG

Дословность = сумма четырёх вещей, не свойство RAG:

1. **Чанки по смыслу:** 1 TG-пост = 1 чанк; 1 раздел книги = 1 чанк; 1 формат = 1 чанк.
   Механическая резка по N токенов разрезает примеры пополам — копировать нечего.
2. **Обрамление в промпте:** ретривнутое подавать как «мои реальные формулировки —
   копируй ИХ обороты и структуру дословно, НЕ пересказывай». (Тот же принцип, что в
   воркфлоу антипаттернов: LLM лучше копирует примеры, чем выполняет правила.)
3. **Объём:** 10–12 кусков (10–12k токенов), не top-3.
4. **Гибридный поиск** (ключевые слова + смысл): корпус набит точными терминами (ВИСП,
   Матрица Дайсона, система кубиков) — чистые эмбеддинги их мажут.

## Юнит-экономика (Opus 4.8)

Вход $5/M · кэш-чтение $0.50/M · выход $25/M.

| Тип запроса | Что в контексте | Вход | Выход | Итого |
|---|---|---|---|---|
| Болтовня | хребет (кэш), thinking off | $0.009 | ~$0.01 | **~2¢** ✅ |
| Короткий сценарий | хребет + форматы + 1 канал TG (всё кэш) | ~$0.02 | ~$0.04 | **~6¢** ✅ |
| Длинный сценарий | хребет (кэш) + куски книги (НЕ кэш ~12k) + thinking | ~$0.07 | ~$0.075 | **~14¢** ⚠️ |

Физически дорогие места на Opus, которые НЕ лечатся без потери качества:

- **Выход $25/M** — сценарий 2–3k токенов = 5–7¢ только на выходе.
- **Поиск по книге** — куски уникальны под запрос → не кэшируются → полный вход $5/M.

Вывод: болтовня и короткий сценарий — в цель; длинный сценарий по книге ~14¢ — нет.

## Рычаги снижения цены

1. **Thinking off для болтовни**, `adaptive` + `effort:medium` только для генерации.
2. **Кэш ретрива внутри диалога:** при итерации сценария («острее хук», «короче») куски
   книги стабильны → брейкпоинт, реплики 2+ читают их по 0.1× (14¢ → ~8¢).
3. **Тугой ретрив:** 10–12k, не 20k. Гибридный поиск.
4. **Один канал TG, не оба** (−25k токенов на коротких сценариях).
5. **Кап выхода по типу** (болтовня 500, сценарий 2.5k).

## Монетизация: квота на ДОРОГУЮ операцию, не на запросы

Курс ~95 ₽/$. План 500 ₽ ≈ $5.3, 1000 ₽ ≈ $10.5. При марже 50% бюджет API = половина
выручки.

| План | Бюджет API/мес | @3¢ | @6¢ | @14¢ |
|---|---|---|---|---|
| 500 ₽ | $2.65 | 88 | 44 | 19 |
| 1000 ₽ | $5.25 | 175 | 87 | 37 |

**Не ставить единый лимит на «запросы».** Квотировать именно генерацию сценариев (она
дорогая), болтовню (~2¢) — отдать безлимитом. Пример сетки, которая отбивается:

- **500 ₽** — безлимит чата + **15 сценариев/мес** → худший случай ≈ $2.5, маржа ~53%.
- **1000 ₽** — безлимит чата + **40 сценариев/мес** → ≈ $5.8, маржа ~45%.

## Фазы реализации

- **Фаза 0 — 🟢 готово (2026-06-15).** `MODEL_ID` → `claude-opus-4-8`; thinking →
  `adaptive` + `output_config.effort` (на Opus 4.8 старый `budget_tokens` даёт 400).
  Файл: `src/app/api/chat/route.ts`.
- **Фаза 1 — 🟢 готово (2026-06-15).** Хребет (SYSTEM_CORE без книги + VOICE +
  ANTIPATTERNS) вынесен в `buildSystem()` и грузится всегда (кэш 1ч). Роутер на Haiku
  (`src/lib/router.ts`) классифицирует запрос (chat/short/long/method) + детерминированный
  fast-path для болтовни (без вызова LLM). Слои подключаются по нужде. Для болтовни
  thinking отключается.
- **Фаза 2 — 🟢 готово (2026-06-15), keyword-вариант.** `src/lib/knowledge-retrieval.ts`:
  книга режется на чанки (по главам + группировка строк ~500 токенов), BM25-поиск, top-K,
  обрамление «копируй дословно». Длинные сценарии грузят релевантные куски вместо всей
  книги. **Семантические эмбеддинги — опциональный апгрейд** (нужен провайдер Voyage/OpenAI
  + pgvector; для дословного воспроизведения keyword обычно достаточно).
- **Фаза 3 — 🟡 частично.** Кэш-структура готова (хребет 1ч + статичные слои за 2-м
  брейкпоинтом + книга/aboutYou после, без кэша). **Квоты на юзера — 🔴 заблокированы
  реальной авторизацией** (п.1 дорожной карты): модели `User` нет, авторизация мок, нет
  серверной идентичности → enforcement невозможен. Дизайн готов (ниже), реализовать после
  реальной авторизации.
