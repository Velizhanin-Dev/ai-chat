# План развития раздела «Канал» (YouTube-аналитика)

> Дорожная карта расширения дашборда «Канал» под методику КМК (хук, удержание,
> превью/ВИСП, вовлечённость). Цель — не «ещё один YouTube Studio», а аналитика,
> которая **меряет то, на чём стоит методика**, и **превращает провалы в действия
> ассистента**. Статусы: 🟢 готово · 🟡 в работе · 🔴 не начато.

Связанные файлы (что трогать при реализации):
- `src/lib/youtube.ts` — вызовы Data API v3 + Analytics API (добавлять сюда новые репорты).
- `src/lib/youtube-types.ts` — типы ответов (общие клиент/сервер).
- `src/app/api/integrations/youtube/data/route.ts` — сборка payload для дашборда.
- `src/components/Channel/ChannelDashboard.tsx` — UI дашборда.
- `src/lib/youtube-client.ts` — клиентские обёртки + форматтеры.

Права уже подключены: **`youtube.readonly` + `yt-analytics.readonly`** — этого хватает
почти на всё ниже (где нужно больше — помечено). Никаких новых OAuth-scopes для
пунктов 1–7 не требуется.

---

## Что уже готово (базовый дашборд) 🟢
- KPI-карточки: подписчики, просмотры всего, число видео, просмотры за 28 дней.
- Area-график просмотров за 28 дней (`youtubeAnalytics.reports`: `views` по `day`).
- Все видео канала с превью, длительностью, просмотрами/лайками/комментами — постраничная
  догрузка (первая страница из `/data` + `videosNextPageToken`, дальше `/videos?pageToken=` по 30,
  автоподгрузка при доскролле + «Показать ещё»).
- Шапка канала (баннер+аватар+описание), состояния skeleton/не подключено/reauth/ошибка.
- **Аналитика по каждому видео** (`fetchVideoAnalytics`, dimensions=video): **удержание**
  (ср. % досмотра) прогресс-баром с цветом по порогам + ср. длительность просмотра +
  суммарное время просмотра. best-effort (видео без данных — без блока удержания).
- **Кривая удержания по клику на видео** (`fetchVideoRetention`, dimensions=
  elapsedVideoTimeRatio): модалка с area-графиком «время ролика (секунды) → сколько зрителей
  ещё смотрит». Ось X — реальные **секунды** (доля длины × длительность ролика из
  `video.duration`; `durationToSeconds` в youtube-client; фолбэк на % доли, если длительность
  неизвестна — напр. видео открыто из лидерборда роста без метаданных) + бейдж relativeRetentionPerformance («выше/ниже среднего · лучше N%
  похожих») + кнопка **«Переписать хук»** (пишет промпт в черновик чата и уводит в
  `/{projectId}/chat`). Роут `GET /api/integrations/youtube/video?projectId=&videoId=`.
- KPI-дельты — инлайн-тренд в карточке (цветная стрелка+% + тихий «за пред. период»).

## ⚠️ Важное ограничение API (заложить в ожидания)
**CTR превью и показы (impressions / impressionsClickThroughRate) публичный YouTube
Analytics API НЕ отдаёт** — они есть только в YouTube Studio. Это боль, т.к. методика
сильно про упаковку (превью/заголовок, ВИСП). Обходные пути:
- показывать **долю трафика из «Рекомендованных»/«Обзор»** как прокси качества упаковки (см. п.2);
- дать **ручной ввод CTR** (пользователь смотрит в Studio, вбивает — мы храним и строим тренд);
- кнопка «Открыть в YouTube Studio» на карточку видео.
Не прятать это от пользователя.

## Приоритет 1 — Удержание (ядро методики) 🟢 ГОТОВО (Этап 2)
Самое ценное. Всё через `yt-analytics.readonly`. Реализовано: ср. % досмотра в KPI и на
карточках видео + **кривая удержания** в модалке видео + relativeRetentionPerformance +
кнопка «Переписать хук» → ассистент. Осталось по желанию: `elapsedVideoTimeRatio` можно
дополнить сравнением с медианой прямо на графике (пунктир).

- **Средний % досмотра** — тренд по каналу + значение на каждом видео.
  Метрики: `averageViewPercentage`, `averageViewDuration`.
- **Кривая удержания видео** — где отваливаются, как отрабатывает хук в первые 15–30 сек.
  Репорт: `dimensions=elapsedVideoTimeRatio`, `metrics=audienceWatchRatio,relativeRetentionPerformance`,
  фильтр `filters=video==<VIDEO_ID>`. Рисуем LineChart 0→100% длины ролика.
- **`relativeRetentionPerformance`** — лучше/хуже похожих роликов YouTube («красная/зелёная зона»).
- UX: клик по видео в сетке → **детальная карточка видео** с кривой удержания.
- 🔗 **Действие ассистента:** провал удержания в начале → кнопка «Переписать хук» уводит
  в чат с подставленным контекстом видео (название/тема/точка провала).

## Приоритет 2 — Источники трафика (про превью и названия) 🟢 ГОТОВО (Этап 3)
- Разбивка **Обзор / Рекомендованные / Поиск YouTube / Внешние / Плейлисты / Подписки…**
  (`fetchTrafficSources`, `dimensions=insightTrafficSourceType`, период-зависимая — в `/data`).
- UX: donut (`@mantine/charts`) + список с долями (%), топ-6 источников + свёрнутое «Другое»,
  русские лейблы, цвета по источникам. Капшен-подсказка про ВИСП/SEO.
- Осталось по желанию: разбивка источников **по конкретному видео** (в модалке видео) +
  🔗 кнопка ассистента «превью-текст и заголовок по ВИСП», если мало «Рекомендованных».

## Приоритет 3 — Динамика подписчиков 🟢 ГОТОВО (Этап 4) + блок «Рост канала» (Этап 7)
- **Блок «Рост канала» (`GrowthSection` в `ChannelDashboard.tsx`)** — два синхронных графика
  на ОБЩЕЙ оси времени (отрезки-бакеты): сверху область просмотров (ось X скрыта, общая с
  нижним), снизу **столбцы прироста подписчиков, РАЗЛОЖЕННЫЕ по видео-драйверам** (`BarChart
  type=stacked`, серия на видео + серая «Другое»). Каждый цветной сегмент = сколько подписчиков
  привёл конкретный ролик в этот отрезок (а не общий прирост). Итоги +N/−N/«чистыми» — из
  дневного ряда (там есть отток), бейджами в шапке.
  - **Рейка релизов под нижним графиком** — кастомный тик оси X (`ReleaseTick`, SVG-`<image>`):
    ровно под столбцом отрезка показываются превью роликов, вышедших в этот отрезок (до 3, дальше
    «+N»); подписи дат прорежены (~8 штук) через `stride`. Выравнивание пиксель-в-пиксель, т.к.
    recharts даёт координаты тика.
  - **Кастомный тултип столбца** (`GrowthTooltip` через `tooltipProps.content`): разложение
    прироста по видео (цвет серии + название + сколько подписчиков), плюс суммарно за отрезок.
  - **Легенда-лидерборд** (`DriverRow`): видео-драйверы с цветом серии, превью, датой выхода и
    вкладом (+N); клик открывает ту же **модалку разбора видео** (`VideoDetailModal`) — если
    ролик есть в недавних, с полными метриками, иначе конструируем минимальный объект. Строка
    «Другое» — сумма неатрибутированного прироста.
  - **Данные — `fetchSubscriberTimeline`** (`youtube.ts`): гранулярность под период (≤28 дн →
    день, ≤90 → неделя, иначе месяц; `granularityFor`/`bucketKeyFor`). Переиспользует уже
    полученные `daily` (просмотры + суммарный прирост канала), `subVideos` (топ-драйверы) и
    `videos` (даты выхода/релизы); добавляет только **≤6 лёгких запросов** дневного ряда по
    каждому драйверу (`fetchVideoDailySubs`, dimensions=day + filters=video==ID). «Другое» =
    прирост отрезка − отнесённое к драйверам (клампится в 0). Тип `SubscriberTimeline` в
    youtube-types, поле `SubscriberDynamics.timeline`. null → фолбэк на прежний простой график
    просмотров.
  - **Ограничение:** релизы берутся из недавних ~12 видео (`videos`), поэтому на окне 365 дней
    старые релизы могут не попасть в рейку (атрибуция подписчиков при этом полная — она из
    Analytics по драйверам). При надобности — тянуть больше publishedAt отдельным дешёвым
    `playlistItems`.
- **(Легаси, заменено)** Прежняя секция «пришло/ушло по дням» (расходящиеся столбцы) + плоский
  список видео-драйверов заменены блоком «Рост канала». Поля `subscribers.daily`/`topVideos` в
  payload остались (используются для итогов/фолбэка).
- **Видео-драйверы** (`fetchSubscriberVideos`, dimensions=video) — по-прежнему источник топ-видео
  за период (net +/−), теперь ещё и вход для таймлайна.
- Осталось по желанию: отдельная выборка «видео-отток» (sort по subscribersLost) +
  🔗 кнопка ассистента «разобрать отток».

## Приоритет 4 — Сравнение периодов (собственно «динамика/рост») 🟢 ГОТОВО (Этап 1)
- **Переключатель периода** 7 / 28 / 90 / 365 дней (SegmentedControl вверху дашборда) —
  влияет на KPI и график; смена периода = мягкий рефреш (карточки не мигают).
- **KPI-карточки за период с дельтой ↑/↓** vs предыдущее равное окно: просмотры,
  время просмотра, новые подписчики (net), **средний % досмотра** (дельта в п.п.).
  Зелёный рост / красный спад / серый ноль; нет прошлого периода → без дельты.
- Лайфтайм-тоталы (всего просмотров, видео) уехали в шапку канала.
- Реализация: `periodRanges(days)` + `fetchPeriodSummary(start,end)` (метрики
  `views,estimatedMinutesWatched,subscribersGained,subscribersLost,averageViewPercentage`),
  два запроса за смежные окна; `fetchDailyAnalytics(start,end)` для графика. Роут
  `data?period=7|28|90|365` (валидируется, дефолт 28). Форматтеры дельт — в youtube-client.
  Проверено на реальном канале (все 4 окна).

## Приоритет 5 — Вовлечённость 🔴
- **Engagement rate** = (лайки + комменты + репосты) / просмотры, тренд по времени.
  Метрики: `likes`, `comments`, `shares`, `views` по `day`.
- Методика много про комменты/СТА — это прямой замер отклика.

## Приоритет 6 — Аудитория (совпадает ли с ЦА из брифа) 🟢 ГОТОВО (Этап 6)
_Реализовано: возраст/пол + гео (русские названия) + устройства (`fetchAudience`, 3 отчёта
параллельно, период-зависимо). Секция «Аудитория» — 4 блока с прогресс-барами. У маленьких
каналов возраст/пол частичны (порог приватности). Осталось: авто-сверка с ЦА из брифа._
- **Возраст/пол**: `dimensions=ageGroup,gender`, `metrics=viewerPercentage`.
- **Гео**: `dimensions=country`. **Устройства**: `dimensions=deviceType` (TV/mobile/desktop — влияет на формат).
- 🔗 Сверять с полем «аудитория» из брифа проекта (`Conversation.brief`) — «попадаем/не попадаем в ЦА».

## Приоритет 7 — Регулярность и топы 🔴
- **Топ-видео за период** — по **времени просмотра**, не только просмотрам (`estimatedMinutesWatched` по `video`).
- **Календарь публикаций** оверлеем на график роста — видна связь «стабильно выкладываю → растёт».
- **Shorts vs длинные** — отдельные метрики, если удастся разделить (по длительности `contentDetails.duration`).

## Сквозная идея — «Аналитика → действие ассистента» (дифференциатор) 🟡 ЧАСТИЧНО (Этап 5)
Главное преимущество перед YouTube Studio — у проблемной метрики сразу есть действие.
- 🟢 **ИИ-разбор видео в модалке** (`POST /api/integrations/youtube/analyze`, тратит 1 запрос
  квоты как ответ в чате): по названию/описанию/тегам/кривой удержания даёт **summary
  (что сильно / что слабо)** + **готовые варианты**: 3 названия по ВИСП, переписанное
  описание, теги — всё с кнопками «Копировать» прямо в окне, без ухода в чат. Кнопка
  «Ещё вариант разбора» (−1 запрос). Генерация — та же методика/голос, что и в чате
  (`buildSystem` вынесен в [src/lib/llm/system.ts](src/lib/llm/system.ts) и переиспользуется).
  Под задачу упаковки промпт урезан (book/formats off, TG-ВИСП on, thinking off → быстрее).
  Гейты как в чате: auth/launch/бриф(проекта)/квота; телеметрия — обычный `recordStat`.
- 🟢 «Обсудить в чате» на видео (префилл-промпт в черновик + переход в `/{projectId}/chat`).
- 🔴 Кнопки-действия на других метриках (мало рекомендаций → превью по ВИСП; отток → разбор).
- ⚠️ Латентность разбора = латентность движка: на Claude ~10–15с, на GLM зависит от нагрузки
  Z.ai (ttft 30–90с). Копим ответ на сервере (не стримим) — модалка показывает лоадер «до минуты».

## Технические заметки
- **Троттлинг/кэш:** Analytics API имеет квоты — кэшировать ответы (напр. 15–30 мин) на
  сервере или в `YouTubeIntegration` снимком; не дёргать на каждый рендер.
- **Batching:** метрики по `dimensions=video` можно тянуть пачкой по видео сразу, не по одному.
- **Пустые данные:** у новых/маленьких каналов часть репортов вернёт пусто — везде
  предусмотреть «данных пока нет» (как уже сделано для графика 28 дней).
- **Права:** всё выше — на текущих scopes. Если понадобятся комменты для модерации/ответов
  из приложения — это уже `youtube.force-ssl` (отдельный consent, обдумать отдельно).
