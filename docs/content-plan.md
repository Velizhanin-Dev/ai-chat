# Контент-план (раздел «Контент-план»)

Пер-проектный раздел: месячная сетка роликов по методике Велижанина в виде
**канбан-доски по статусам**. Статус: **🟡 Фаза 1 готова** (генерация + доска +
статусы + DnD + ручное добавление + архив месяцев). Не протестировано на живой
генерации (нужен рабочий провайдер модели).

Пример-эталон (Google-таблица клиента): листы `июнь-июль` / `май` (месяцы, прошлые
хранятся) + `шортс` + `Лестница Ханта` / `портреты ЦА` / `воронка` (опорные листы).
Методика количества/структуры — `CONTENT_PLAN_GUIDE` (`knowledge-base-content-plans.ts`,
8–12 роликов/мес, поля строки ролика).

## Решения по UX (согласованы с заказчиком)

- **Вид — канбан по статусам** (не таблица): колонки Идея → В работе → Опубликовано,
  карточки перетаскиваются (DnD). Отменённые — свёрнуты в аккордеон.
- **Связь с YouTube** — автоподбор по похожести названия + ручная привязка + импорт
  опубликованного ролика (Фаза 2). Привязанный ролик → реальные просмотры на карточке,
  статус «опубликовано».
- **Статусы:** `idea` · `in_progress` · `published` · `cancelled`.
- **Опорные блоки** (Фаза 3): сетка шортсов, портреты ЦА, лестница Ханта / воронка.
- **Доступ — публичный** (все залогиненные, не только админы). Вкладка `content-plan` в
  `TopNav` (beta), вне `(locked)`.
- **Стоимость:** генерация плана = **25 запросов** (`CONTENT_PLAN_GENERATE_QUOTA_COST`);
  переделка части одной карточки ИИ = **1 запрос** (`CONTENT_PLAN_EDIT_QUOTA_COST`, Фаза 2);
  ручное добавление/правка — бесплатно.

## Реализация (Фаза 1)

- **Чистый модуль** [content-plan.ts](../src/lib/content-plan.ts): типы, статусы
  (`STATUS_META`, `BOARD_COLUMNS`), форматы (охватное/экспертное/продающее), ВИСП/СТА,
  витрина (`ContentPlanView`/`VideoView`), стоимости, помощники месяца.
- **Сервер** [content-plan-server.ts](../src/lib/content-plan-server.ts): `generatePlanVideos`
  (роут на `content_plan` → `buildSystem` с `CONTENT_PLAN_GUIDE` + бриф → строгий JSON →
  `extractVideos` нормализует под модель), мапперы `toPlanView`/`toVideoView`, проверки
  владения `planConversation`/`videoPlanId`.
- **Данные:** `ContentPlan` (пер-проект, `period`+`label`, опорные блоки JSON) +
  `ContentPlanVideo` (поля методики: `titles[]`/`previewTexts[]`/`format`/`huntStage`/
  `pain`/`questions[]`/`nativeClose`/`cta`/`visp`/`reference`/`whyWorks`/`opening` +
  `status`/`kind`/`source` + связь `youtubeVideoId`/`thumbnail`/`views`). Миграция
  `add_content_plan`.
- **API** `src/app/api/content-plan/*`: `GET /` (список планов проекта), `POST /`
  (генерация, 25 квоты, гейт auth/launch/владение/квота), `GET|DELETE /[id]`,
  `POST /[id]` (добавить ролик вручную), `PATCH|DELETE /video/[id]` (статус/поля/удаление).
  Клиент — [content-plan-client.ts](../src/lib/content-plan-client.ts).
- **UI** `src/components/ContentPlan/`: `ContentPlanBoard` (оркестратор: список планов,
  переключатель месяца `Select`, генерация `Popover` с числом роликов, канбан, empty-state),
  `VideoCard` (формат/ВИСП/превью/просмотры/источник, `draggable`), `VideoDrawer` (все поля
  методики, правка, смена статуса, удаление). **DnD — нативный HTML5** (без зависимостей):
  drag карточки → drop в колонку → оптимистичный PATCH статуса + откат при ошибке; подсветка
  колонки `.cp-col-over`. На тач-устройствах DnD неудобен — статус меняется кнопками в панели.
  CSS — блок «Контент-план (канбан)» в globals.css. Роут `src/app/[projectId]/content-plan/`,
  вкладка публичная (middleware + `PROJECT_TAB_RE` в AppShell обновлены).

## Фаза 2 — связь с YouTube + переделка ИИ (готово)

- **Автоподбор** — `titleSimilarity`/`bestMatch` в [content-plan.ts](../src/lib/content-plan.ts):
  Жаккар по словам названия (нормализация регистра/пунктуации/ё, слова >2 букв), порог
  `MATCH_THRESHOLD = 0.4`. В пикере сверху блок «Похоже на твой ролик X → Связать», в списке
  подходящие помечены бейджем «похоже», сортировка по похожести. ⚠️ regex без `\p{…}/u` и без
  итерации `Set` — иначе падает на текущем `target` компилятора.
- **Пикер** [LinkVideoModal.tsx](../src/components/ContentPlan/LinkVideoModal.tsx): список видео
  канала (поиск по названию, превью, просмотры). Используется и для **привязки** к карточке, и
  для **импорта** нового ролика (кнопка «Импорт с канала» на доске).
- **Источник видео** — `GET /api/content-plan/channel-videos?projectId=` (окно 3 года через
  `fetchPeriodVideos`, in-memory кэш 15 мин на проект; `connected:false`, если канал не подключён).
- **Привязка** — `PATCH /api/content-plan/video/[id]` с `youtubeVideoId`/`thumbnail`/`views`:
  сохраняет снимок и **авто-ставит статус `published`** (если статус не задан явно в том же
  запросе). Отвязка (`youtubeVideoId: null`) чистит связь, статус не трогает. Импорт —
  `POST /api/content-plan/[id]` с `youtubeVideoId` → `source: "imported"`, `status: "published"`.
- **Переделка части карточки ИИ** — `POST /api/content-plan/video/[id]/regenerate`,
  **1 запрос квоты** (`CONTENT_PLAN_EDIT_QUOTA_COST`), списывается после успеха. Части:
  `titles` / `previewTexts` / `questions` / `format` (`REGEN_PARTS`). Промпт тюнингован как у
  ИИ-разбора видео (`category:"chat"` → без thinking, книга/форматы off, слой ВИСП on),
  ответ — строгий JSON. Кнопки — в `VideoDrawer` («Переделать с ИИ · 1 запрос за часть»),
  клиент оптимистично списывает квоту (`bumpRequestsUsed`).
- **Ширина страницы:** раздел добавлен в `wideRoute` (`AppShell`) — рендерится во всю ширину,
  как «Аналитика» (канбану узкая колонка `maw 900` ломает раскладку).

Проверено вживую на моках: автоподбор нашёл нужный ролик, «Связать» перенесло карточку в
«Опубликовано» с просмотрами, переделка названия обновила карточку и доску.

## Фаза 3 — опорные блоки + ресинк цифр (готово)

- **Опорные блоки** — `POST /api/content-plan/[id]/blocks` с `block`:
  `audience` (3–4 портрета ЦА: кто, стадия Ханта, боли от 1 лица, что оттолкнёт),
  `hunt` (5 ступеней лестницы под нишу: состояние → внутренние диалоги → что заходит → темы),
  `funnel` (доли охватное/экспертное/продающее + зачем) — **1 запрос** каждый;
  `shorts` (лёгкая сетка из 8 шортсов: хук-опенинг + референс + боль) — **5 запросов**.
  Стоимости — `CONTENT_PLAN_BLOCK_QUOTA_COST` / `CONTENT_PLAN_SHORTS_QUOTA_COST` (наши цифры,
  не из методики — правятся в [content-plan.ts](../src/lib/content-plan.ts)). Списываются после
  успеха, клиент оптимистично бампает квоту.
- **Генерация** — `generateBlock` в [content-plan-server.ts](../src/lib/content-plan-server.ts):
  эталон контент-плана + ВИСП-слой подключены, книга/форматы off, `category:"chat"` (без
  thinking — это структурная выжимка); слой YouTube-транскриптов включается только для шортсов.
  Строгий JSON, нормализация под типы `Persona`/`HuntStep`/`Funnel`. Шортсы разбираются тем же
  `extractVideos` и пишутся как `ContentPlanVideo(kind="short")`; пересборка заменяет прошлые
  ai-шортсы, ручные не трогает.
- **UI** — [SupportBlocks.tsx](../src/components/ContentPlan/SupportBlocks.tsx): аккордеон из 4
  блоков, у каждого бейдж «готово / не собран», пояснение «зачем» и кнопка «Собрать · N».
  Портреты и ступени — карточки `.cp-block`, воронка — прогресс-бары по форматам, шортсы —
  плиточная сетка `.cp-shorts` (карточка кликабельна → та же детальная панель).
  ⚠️ **Канбан показывает только лонги** (`kind !== "short"`), шортсы — отдельной сеткой: у них
  своя природа (верх воронки, нарезки/реакции) и облегчённые поля.
- **Ресинк просмотров** — `POST /api/content-plan/[id]/resync` (**квоту не тратит**):
  обновляет `views`/`thumbnail` у привязанных роликов из свежего списка канала. Вызывается
  **автоматически при открытии плана** (из кэша, YouTube не дёргается) и по кнопке
  **«Обновить цифры»** (`?force=1` — мимо кэша). Логика — `resyncPlanViews`; список видео канала
  вынесен в общий [content-plan-channel.ts](../src/lib/content-plan-channel.ts) (один кэш 15 мин
  на пикер и ресинк, чтобы не ходить в YouTube дважды).

Все три фазы закрыты. Проверено типами; UI Фазы 3 и ресинк вживую не гонял (по просьбе
заказчика — проверяет сам).

## Правки по итогам обкатки (UX)

- **Количество роликов ФИКСИРОВАНО — 7** (`PLAN_VIDEO_COUNT`). Выбора у пользователя нет:
  поповер с `NumberInput` убран, осталась кнопка «Сгенерировать план» с тултипом
  «7 роликов · 25 запросов». Сервер игнорирует `count` из тела и всегда берёт константу.
  ⚠️ Методика допускает 8–12 — решение заказчика перебивает; менять тут.
- **Автосохранение вместо кнопки «Сохранить»** (`VideoDrawer`): debounce 800 мс на изменение
  полей + дозапись при закрытии панели. Индикатор «сохранено» в шапке. Статус и привязка
  сохраняются мгновенно (не через debounce). ⚠️ Автосейв сравнивает слепок (`savedSnapshot`),
  иначе подстановка ответа сервера триггерит эхо-запрос.
- **Название видео — селектор вариантов + правка**: `Select` со всеми вариантами (виден при
  2+), выбранный переносится в `titles[0]` (карточка на доске показывает именно его), ниже
  `Textarea` для правки выбранного.
- **Подсказка (?) у лестницы Ханта** — `Popover` с 5 ступенями (`HUNT_LADDER_HINT` в
  content-plan.ts) и пометкой «большинство охватных — стадии 2 и 4».
- **«Сгенерировать сценарий»** — кнопка в панели: собирает все вводные ролика (название,
  превью, формат, Хант, боль, почему залетит, опенинг, 10 вопросов, закрытие, референс) в
  промпт, кладёт через `prefillInput` и уводит в чат проекта.
  - ⚠️ **Грабли (чинили):** `ChatInput` реагировал на РОСТ `prefill.seq`, а `useRef`
    инициализировался текущим значением при монтировании. При переходе из другого раздела
    prefill ставится ДО монтирования чата → компонент видел новый seq как «начальный» и молча
    терял текст (кнопка «ничего не делала»). Из `QuickActions`/`ChatWelcome` работало, потому
    что чат уже был смонтирован. Теперь модель «потребления»: композер забирает текст и гасит
    его (`prefillConsumed` в chatSlice) — работает и при переходе из раздела, и при повторном
    клике по той же плитке. Восстановление черновика из localStorage prefill не перетирает
    (оно пишет только в пустое поле).
- **Вёрстка:** свитч «Без спикера» выровнен по центру относительно селекта формата (был
  прижат вниз); отступ подпись↔инпут увеличен до 8px (`.cp-drawer .mantine-InputWrapper-label`
  + класс `.cp-label` для блоков без Input).
- **Шапка страницы убрана** (заголовок «Контент-план» + подзаголовок) — раздел и так подписан
  вкладкой в `TopNav`.
