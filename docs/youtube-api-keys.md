# Ключи YouTube API для раздела «Конкуренты в нише»

Инструкция: как завести ключи, зачем их несколько и что делать, когда квота
кончится. Занимает ~5 минут на ключ.

---

## Зачем вообще отдельные ключи

Раздел «Конкуренты» ищет чужие ролики через YouTube Data API. Один поисковый
запрос стоит **100 units** из 10 000 суточных, тогда как любой другой вызов —
1 unit. То есть **100 поисков в день, и квота на нуле**.

Квота считается не на пользователя, а на **Google Cloud проект**, чьим ключом
(или OAuth-клиентом) сделан запрос. Аналитика канала ходит в API под токеном
пользователя, но списывается всё равно с нашего проекта — того, где заведён
`GOOGLE_CLIENT_ID`.

Отсюда правило:

> ⚠️ Ключи для поиска должны быть из **ОТДЕЛЬНЫХ** Google Cloud проектов — не из
> того, где живёт OAuth-интеграция канала.

Иначе первый же активный день поиска выжжет общую квоту, и раздел «Аналитика»
перестанет открываться **у всех пользователей сразу**.

По той же причине несколько ключей внутри одного проекта бессмысленны: пять
ключей одного проекта дадут те же 10 000 units, а не 50 000. **Один проект =
один ключ = 10 000 units в сутки.**

---

## Как завести один ключ

Всё делается в [Google Cloud Console](https://console.cloud.google.com).
Аккаунт подойдёт любой — можно тот же, что и для интеграции канала: ограничение
на проекты, а не на аккаунты.

### 1. Создать новый проект

Вверху страницы — выпадающий список проектов → **New Project**.

- **Project name**: что-то узнаваемое, например `velizhanin-yt-search-1`
  (следующие — `-2`, `-3`: по имени сразу видно, какой ключ где).
- Организацию/биллинг подключать **не нужно** — Data API в пределах бесплатной
  квоты работает без карты.

Нажать **Create** и дождаться, пока проект станет активным (значок в шапке
переключится на новый).

### 2. Включить YouTube Data API v3

В поиске вверху набрать **YouTube Data API v3** → открыть карточку API →
кнопка **Enable**.

⚠️ Убедитесь, что в шапке выбран **новый** проект, а не тот, где OAuth. Это
самая частая ошибка: API включается не туда, а ключ потом не работает.

**YouTube Analytics API включать не надо** — он нужен только для аналитики
своего канала и работает по OAuth.

### 3. Создать ключ

**APIs & Services → Credentials → Create credentials → API key**.

Ключ появится сразу, в формате `AIzaSy...`. Скопировать.

### 4. Ограничить ключ (рекомендуется, но не обязательно)

Нажать **Edit API key** и выставить:

- **API restrictions** → *Restrict key* → отметить только **YouTube Data API v3**.
  Так утёкший ключ нельзя будет использовать для других API.
- **Application restrictions** → оставить **None**.
  ⚠️ Ограничение по IP тут не годится: запросы идут с сервера, а «HTTP referrers»
  — вообще про браузер. Если очень хочется, можно указать IP прод-сервера, но
  тогда ключ перестанет работать при смене сервера или локально.

Сохранить.

### 5. Повторить нужное число раз

Каждый следующий ключ — **новый проект**, шаги 1–4 заново.

Сколько заводить: считайте от нагрузки. Один поиск в разделе = число ключевых
слов × 100 units, то есть при трёх словах ~300 units. **10 000 units ≈ 33 таких
поиска на ключ в сутки.** Для админского раздела 2–3 ключа с запасом.

## Куда прописать

В `.env` на сервере, **через запятую, без пробелов и кавычек**:

```
YOUTUBE_API_KEYS=AIzaSyA...key1,AIzaSyB...key2,AIzaSyC...key3
```

Применить:

```bash
docker compose up -d
```

`docker-compose.yml` читает `.env` через `env_file`, так что править compose не
нужно.

Проверка: зайти в проект → вкладка **Конкуренты**. Под кнопкой «Найти» пишется
цена поиска в units и остаток по пулу на сегодня. Если ключей не видно —
переменная не доехала до контейнера.

## Как работает ротация

Сидим на первом ключе, пока он не упрётся в суточный лимит, затем автоматически
переключаемся на следующий. Пользователь ротацию не замечает: запрос молча
повторяется другим ключом.

Счётчики обнуляются **в полночь по тихоокеанскому времени** — это ~10:00–11:00
по Москве (плавает из-за перехода на летнее время в США). Именно тогда Google
сбрасывает квоту, поэтому свой суточный отсчёт мы ведём по тому же часовому поясу.

⚠️ Счётчик живёт в памяти процесса и обнуляется при перезапуске контейнера.
Поэтому истина не в нём, а в ответе Google: если ключ отвечает 403
`quotaExceeded`, он выводится из игры до конца суток независимо от счётчика.
Счётчик лишь экономит заведомо пустые попытки.

Когда исчерпаны все ключи, поиск отвечает понятной ошибкой и предлагает подождать
сброса. Уже полученная выдача при этом остаётся — она кэшируется на 6 часов, и
фильтры (порог, минимум просмотров, шортсы/лонги) считаются на клиенте, квоту не
тратят.

## Если что-то не работает

**«Поиск не настроен»** — переменная `YOUTUBE_API_KEYS` пустая или не доехала в
контейнер. Проверить: `docker compose exec app printenv YOUTUBE_API_KEYS`.

**В логах `ключ #N невалиден — исключён из пула на сегодня`** — ключ скопирован
с обрезкой, удалён в консоли, либо в его проекте не включён YouTube Data API v3.
Чаще всего последнее: API включили в старом проекте, а ключ создали в новом.

**В логах `ключ #N исчерпал суточную квоту, переключаюсь`** — это норма, так и
задумано. Тревожно, только если такое видно по всем ключам сразу и рано днём:
значит, ключей мало для текущей нагрузки.

**Квоту хочется больше** — либо ещё один проект с ключом (бесплатно, минуты),
либо запрос на увеличение квоты в Google (форма в *IAM & Admin → Quotas*,
рассматривается неделями и требует описания продукта). Первое проще.

## Связанные переменные

| Переменная | Смысл |
|---|---|
| `YOUTUBE_API_KEYS` | Ключи через запятую. Пусто → раздел показывает «поиск не настроен», остальное приложение работает как обычно. |
| `YOUTUBE_API_KEY` | Фолбэк на один ключ, если пул не нужен. |
| `YOUTUBE_API_KEY_DAILY_UNITS` | Суточный бюджет ОДНОГО ключа, по умолчанию 10000 (реальный лимит Google). Понижать имеет смысл, только если тем же проектом пользуется что-то ещё. |

`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — это **другая** история (OAuth к
каналу пользователя, разделы «Аналитика» и «Контент-план»). К поиску конкурентов
отношения не имеют и трогать их не надо.
