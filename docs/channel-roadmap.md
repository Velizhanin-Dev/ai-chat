# Дорожная карта канала (шаги вместо «разбора по 7 параметрам»)

Спека со слов заказчика. Статус: **🟡 движок реализован** (не протестирован на живом
канале — нужен подключённый YouTube с данными). Связано с
[achievements.md](achievements.md) — закрытый шаг зажигает ачивку-шаг (`completeStep`).

## Реализация (движок)

- **Ядро — [src/lib/roadmap.ts](../src/lib/roadmap.ts)** (чистое, клиент/сервер): каталог 5
  шагов (`ROADMAP_STEPS`: title/why/todo/CTA), пороги (`ROADMAP_THRESHOLDS` — в одном месте,
  часть из методики, часть дефолты-помечены), `RoadmapSignals`, предикат `stepApplies`
  (он же для отбора и для проверки «проблема ушла»), гейт `unlockedCount`/`unlockAt` («1 шаг
  раз в 2 дня»), `statusOf` (locked/open/claimed/done), верификация `isStepVerified`
  (сигнал улучшился ИЛИ новое видео), `buildRoadmapView`.
- **Сервер — [src/lib/roadmap-server.ts](../src/lib/roadmap-server.ts)**: `collectSignals`
  (сигналы из `fetchPeriodVideos` + `fetchVideoSubs` за 365 дн → доли/конверсии),
  `getRoadmap` (строит/освежает план, TTL сигналов 30 мин, refresh форсит), `claimRoadmapStep`
  («Сделал» → claimed + baseline-снапшот), `verifyRoadmapAfterDiagnose` (хук из разбора).
  Закрытый шаг → `completeStep(userId, key)` (ачивка). ⚠️ Проблема ушла (`!stepApplies`) →
  шаг done даже без клика; claimed без подтверждения → галочка отжимается.
- **Данные — `ChannelRoadmap`** (миграция `add_channel_roadmap`, `@unique conversationId`,
  cascade): `signals` (Json) + `signalsAt` + `steps` (Json `RoadmapStepState[]`). Статусы НЕ
  хранятся — считаются `statusOf`.
- **API** `GET/POST /api/channel/roadmap?projectId=` (claim/refresh), клиент
  [roadmap-client.ts](../src/lib/roadmap-client.ts). Квоту не тратит.
- **UI — [RoadmapCard.tsx](../src/components/Channel/RoadmapCard.tsx)** в разделе «Канал»
  (под строкой канал+достижения): шаги с маркером-статусом, CTA (чат/превью/Студия), «Сделал»,
  «Проверить», прогресс N/M, состояния locked/claimed/done, «Канал в порядке» при пустом плане.
- **Хук разбора**: `POST /api/integrations/youtube/diagnose` после сохранения разбора зовёт
  `verifyRoadmapAfterDiagnose` (fire-and-forget) — разбор канала и есть «переразбор каждые 2 дня».

Открытые вопросы (пороги ER/удержания — дефолты; форма шагов — бинарная) решены дефолтами,
помечены в `ROADMAP_THRESHOLDS`; правятся там же.

---

## Спека (со слов заказчика)

Идея: вместо круга с баллами человек получает **дорожную карту из ~10 шагов** —
что делать по порядку, почему и как. Шаги подбираются по цифрам канала, открываются
**по одному раз в 2 дня**, отмечаются галочкой, а выполнение **проверяется по данным**,
а не по нажатию.

---

## Диагностические правила (какой шаг кому выпадает)

### Шаг 1. SEO — «пересеошить все видосы»
**Условие:** больше половины роликов набрали **меньше 100 просмотров**.
**Вывод:** человек, скорее всего, не разбирается в SEO вообще.
**Что даём:** объяснение, зачем SEO, что именно делать (теги, описание, название,
тайм-коды) — берём из готового слоя базы знаний «SEO-оптимизация: внутренний курс
шеф-редакторов студии» (`knowledge-base-youtube.ts`).

### Шаг 2. CTR — превью и темы
**Условие:** много длинных роликов, у которых **до 1000 просмотров**.
**Вывод:** проблема, скорее всего, в CTR — он не дотягивает до нормы.
**Порядок работы:** сперва ещё раз проверить SEO (там тоже может быть плохо), потом
менять превью. Слабый CTR бывает по двум причинам:
1. **Слишком узкие темы.** По VidIQ / Яндекс.Вордстату меньше **10 000 запросов в
   месяц** → надо расширять аудиторию, подниматься выше по **лестнице Ханта**.
2. **Слабые триггеры на превью** → переделать превью по **ВИСП** (выгода, интрига,
   срочность, причастность).

### Шаг 3. Конверсия в подписку
**Условие:** по последним **20 видео** низкая конверсия в подписку.
**Что даём:** отправляем к курсу «Конверсия в подписку», просим ответить себе на
вопрос «что получит зритель, посмотрев все мои видео?», после курса — пройти по
роликам и добавить недостающие CTA на подписку.

### Шаг 4. Вовлечение (ER)
**Условие:** по последним **20 видео** низкий ER = (лайки + комментарии) / просмотры.
**Вывод:** контент недостаточно эмоционален, нет призывов к действию — поставить
лайк, написать комментарий.

### Шаг 5. Удержание
**Условие:** низкое удержание.
**Что делать:**
1. **Сократить хронометраж.** Пример: все ролики по 20 минут, удержание 20% — это
   очень слабо. Вырезать воду (можно прямо в редакторе YouTube Аналитики).
2. Поработать над сценарием, харизмой, форматом.

## Как выглядит карта для пользователя

Условные 10 шагов, **открываются по одному раз в 2 дня**:

1. **Заманьячить SEO.** Сделал → ставит галочку.
2. **Исправить превью с низким CTR.** Ведём пользователя **в чат**, где ассистент
   разбирает с ним тексты на превью и оформление по законам его ниши.
3. **Исправить видео с низким удержанием.** Либо подрезать сразу в Творческой студии
   YouTube, либо перемонтировать.
4. Дальше — по правилам из блока выше (конверсия в подписку, вовлечение) **плюс то,
   что Коля скажет на разборах канала** (пополняем по мере разборов).

---

## Проверка выполнения (ключевое: галочку нельзя просто тыкнуть)

- Раз в 2 дня делается **переразбор канала** — за это время успевает собраться новая
  аудитория.
- Если с прошлого разбора **ничего не изменилось**, но на канале **появилось новое
  видео**, — засчитываем, галочка остаётся.
- Если изменений нет и нового видео нет — **галочка отжимается** (шаг возвращается
  в работу).

## Что надо решить перед реализацией

- Точные пороги «низкой» конверсии в подписку, ER и удержания (в правилах 1–2 цифры
  заданы явно: <100 просмотров, <1000 просмотров, <10 000 запросов; для 3–5 порогов
  нет). Часть норм есть в `channel-params.ts` и базе знаний — брать оттуда, не
  выдумывать.
- Откуда берём число запросов по теме (VidIQ / Вордстат) — своей интеграции нет,
  см. [vidiq-integration-plan.md](vidiq-integration-plan.md).
- Судьба старого «разбора по 7 параметрам»: карта шагов его заменяет на первом
  экране, но сам разбор и `ChannelAnalysis` остаются как источник цифр.
