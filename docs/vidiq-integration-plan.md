# План интеграции идей vidIQ в Velizhanin AI

> Разбор актуального функционала **vidIQ** (крупнейший инструмент роста YouTube, 20M+
> пользователей) и план, **какие рабочие идеи взять в наш продукт и как переосмыслить их
> под методику КМК**. Мы НЕ клонируем vidIQ — выцепляем то, что усиливает нашу петлю
> «аналитика → действие ассистента» и нашу методику (ВИСП, лестница Ханта, хук/удержание,
> Матрица бесконечного контента, колесо пиздатости, DISC-харизма).
>
> Статусы: 🟢 уже есть у нас · 🟡 частично · 🔴 не начато · ⛔ сознательно не берём.
> Связанные файлы проекта помечены по ходу. Дата разбора: 2026-07.

## 0. Философская рамка (читать первым — от неё зависит отбор)

**vidIQ и Велижанин смотрят на рост с разных сторон:**

| | vidIQ | Методика КМК (наш продукт) |
|---|---|---|
| Ядро | SEO/discovery/data: keyword volume, теги, SEO-score, VPH | Упаковка (ВИСП превью/заголовки), хук/удержание, системность, личность |
| Единица работы | Метрика + метаданные | Готовый артефакт в голосе автора + действие |
| Отношение к тегам/SEO | Центральное (SEO-score, keyword score) | Второстепенное — Велижанин против «оптимизации ради тегов», рост из **упаковки и удержания** |
| Тон | Дашборд-инструмент | Живой продюсер, методика **молча** |

**Вывод для отбора.** Берём у vidIQ сильные механики **discovery (залёты/тренды), coaching
(проактивный совет), audit (оценка канала), competitor-насмотренность** — но переворачиваем
их через КМК. **Сырой SEO-tag-scoring и keyword-volume как ядро НЕ копируем** (см. §4) — это
против философии методики и уводит пользователя не туда.

**Наш дифференциатор уже сильнее, чем у vidIQ в одном:** у нас **методика молча + голос
конкретного автора + бриф/DISC-персонализация**. vidIQ-совет обезличен («добавь 5 тегов»),
наш — от Велижанина, под нишу и типаж юзера. Каждая идея ниже должна это усиливать, а не
разбавлять.

## 2. Что у нас УЖЕ перекрывает vidIQ (чтобы не изобретать)

- 🟢 **ИИ-разбор упаковки видео** (`POST /api/integrations/youtube/analyze`) ≈ vidIQ *Optimize +
  Title/Description Generator*: по названию/описанию/тегам/удержанию даёт summary + ВИСП-названия,
  описание, теги. Мы уже генеративны и в голосе методики.
- 🟢 **Дашборд «Канал»** (`ChannelDashboard.tsx`) ≈ vidIQ *Analytics*: KPI за период с дельтами,
  удержание + кривая удержания, источники трафика, **блок «Рост канала» с атрибуцией подписчиков
  по видео**, аудитория. Местами глубже vidIQ (атрибуция прироста по конкретным роликам).
- 🟢 **Контент-планы + Матрица бесконечного контента** ≈ фундамент под *Daily Ideas*: движок тем
  уже есть (`knowledge-base-content-plans.ts`), не хватает проактивной подачи «идея дня».
- 🟢 **Колесо пиздатости (8 осей)** в базе знаний ≈ *Scorecard*: методология оценки канала уже
  описана (`knowledge-base-tg-closed.ts`), нет автоматизированного виджета.
- 🟢 **Насмотренность/конкуренты** уже упомянуты в контент-планах как опорный лист ≈ *Competitors*:
  концепция есть, инструмента нет.
- 🟢 **Чат-ассистент** ≈ *AI Coach*: есть, но **пока не видит метрик канала** (главный гэп, см. P1.1).

**Вывод:** мы не догоняем vidIQ с нуля — мы в середине пути. Ключевые гэпы — сделать ассистента
**аналитик-осведомлённым**, **проактивным** и добавить **разведку чужих залётов**.

## 3. Приоритеты

### Приоритет 1 — усилить ассистента на НАШИХ данных (дёшево, высокий fit) 🔴

Почти всё здесь — промпт-инжиниринг поверх уже собираемых данных (`buildSystem` в
[src/lib/llm/system.ts](../src/lib/llm/system.ts) + существующие YouTube-репорты). Дорогой
инфраструктуры не требует, кормит наш главный дифференциатор.

1. **Аналитик-ассистент (аналог AI Coach).** 🟢 ГОТОВО
   - *vidIQ:* чат подключён к аналитике канала — «почему падает watch time?» → анализ метрик +
     конкретные действия.
   - *Сделано:* если у проекта подключён YouTube, `POST /api/chat` подставляет в промпт
     **компактный снимок канала** (`buildChannelBlock` в system.ts: канал + KPI 28д с трендом +
     топ-видео с удержанием + трафик + драйверы подписчиков). Нейронка разбирает предметно по
     цифрам, в голосе Велижанина, методику молча. Снимок кэшируется отдельно (30 мин по проекту,
     `getChannelSnapshotCached` в youtube.ts) — **YouTube не дёргается на каждое сообщение**;
     сбой чат не роняет. Плюс: когда канал НЕ подключён и данные реально нужны — модель по делу
     предлагает подключить с кнопкой в чате (маркер `[[connect_youtube]]` → `ConnectYouTubeCta`,
     двойной гейт по `apiYouTubeStatus`). См. CLAUDE.md → «P1: аналитик-осведомлённый ассистент».
   - *Осталось по желанию:* явная кнопка «Разобрать канал» на дашборде (сейчас работает через
     обычный вопрос в чате); отдельная «analytics»-категория роутера, чтобы снимок тянулся только
     на аналитических вопросах (сейчас всегда при подключённом канале — но кэш это дешевит).

2. **«Ход дня» (аналог Daily Ideas / AI Coach daily session).** 🔴
   - *vidIQ:* раз в день — одна лучшая идея видео под канал и тренды.
   - *Наша адаптация:* ежедневный **один конкретный ход** под нишу/бриф и **Матрицу бесконечного
     контента** — тема + ВИСП-название + формат (охватное/экспертное) + стадия Ханта. Не 50
     идей-простыней (у нас лимит артефактов), а **один доведённый шаг** «сегодня сними это».
   - *Ценность для SaaS:* повод возвращаться каждый день (retention продукта, не только канала).
   - *Куда встроить:* карточка на `/{projectId}/chat` или экране проекта; генерится по крону/
     по первому заходу за день, кэшируется на сутки. Тратит квоту (или отдельный лимит).
   - *Стоимость:* низкая-средняя; следить за расходом квоты (кэш на день обязателен).

3. **Автоаудит канала = «Колесо пиздатости» (аналог Scorecard / Channel Audit).** 🔴
   - *vidIQ:* грейдит канал по осям (рост, SEO, engagement, outliers…) + рекомендации.
   - *Наша адаптация:* автоматический аудит по **8 осям колеса пиздатости** (наш ассет!) —
     упаковка/ВИСП-превью, хук/удержание, регулярность, ниша/Хант, охватное×экспертное, СТА и т.д.
     Каждой оси — оценка (из метрик + разбора роликов) и **действие ассистента**. НЕ SEO-score.
   - *UI:* радар/колесо (8 осей) на дашборде + список «слабых осей» с кнопкой «исправить с
     ассистентом» → чат с контекстом.
   - *Стоимость:* средняя (агрегация метрик + 1 генеративный проход на разбор осей).

4. **Проактивные флаги на видео (аналог Optimize).** 🔴→🟡
   - *vidIQ:* авто-ревью роликов с флагами «что улучшить».
   - *Наша адаптация:* на карточках видео дашборда — **авто-флаги по порогам КМК**: удержание <
     порога → «слабый хук, переписать»; мало «Рекомендованных» в источниках → «превью/заголовок по
     ВИСП»; отток подписчиков на ролике → «разобрать». Каждый флаг = кнопка в чат/ИИ-разбор.
     Пороговую логику считаем на клиенте/сервере из уже имеющихся метрик (бесплатно), генерацию —
     по клику.
   - *Стоимость:* флаги — бесплатно (пороги); действие — квота по клику.

5. **Шортсы из пиков удержания (переосмысление Video Clipping).** 🔴
   - *vidIQ:* нарезает шортсы из лонга (видеообработка).
   - *Наша адаптация БЕЗ видеообработки:* у нас есть **кривая удержания** (`fetchVideoRetention`).
     Находим **пики/плато удержания** → отдаём **таймкоды-кандидаты под шортс** + ассистент пишет
     хук/подводку к каждому. Совпадает с методикой «шортсы + лонги в связке».
   - *Куда встроить:* в модалку видео рядом с кривой удержания — блок «Нарезать шортсы» (таймкоды
     пиков + сгенерированные заголовки шортсов).
   - *Стоимость:* низкая (данные есть; 1 генеративный проход).

### Приоритет 2 — разведка и конкуренты (нужно больше данных/квоты YouTube API) 🔴

Здесь ценность высокая (насмотренность — прямо в методике), но требуется **YouTube Data API
search** (дорогой по квоте) и аккуратный кэш.

6. **«Разведка залётов» (аналог Outliers) — сильнейшая идея vidIQ.** 🔴
   - *vidIQ:* показывает чужие видео, которые **обогнали базлайн своего канала** (Outlier Score =
     множитель к среднему: 2–5× синий, 5–10× фиолетовый, >10× красный) + **VPH** (моментум сейчас).
     Действия: «дай идеи», «найти похожие», «добавить в конкуренты».
   - *Наша адаптация:* «Что залетает в твоей нише» → по ключам ниши/брифа ищем ролики, считаем
     **свой outlier-множитель** (views ролика / средние просмотры канала-источника) + VPH, фильтры
     (свежесть, длина, формат). **Ключевое отличие от vidIQ:** на каждый залёт — кнопка «Сделать
     под мой канал» → ассистент выдаёт **ВИСП-название + сценарий + стадию Ханта** в голосе автора
     (не просто «вот чужое видео»). Прямо кормит **Матрицу бесконечного контента** и контент-план.
   - *Технически:* `search.list` (100 units/запрос, дневная квота по умолчанию 10k) + `videos.list`
     + `channels.list` для базлайна. **Обязателен серверный кэш** (15–60 мин) и лимит на юзера.
     Возможно — предрасчёт по нишам, а не по каждому клику.
   - *Стоимость:* высокая по квоте API + генерация по клику. Продумать лимиты/кэш до реализации.

7. **Слежка за конкурентами (аналог Competitors).** 🔴
   - *vidIQ:* мониторит каналы-конкуренты: новые видео, расписание, скорость просмотров.
   - *Наша адаптация:* в проекте — список **каналов для насмотренности** (уже наш опорный лист).
     Следим за их новыми/залетевшими роликами, регулярностью; связка с «Разведкой залётов» (п.6) и
     контент-планом. Действие: «адаптировать их формат под меня».
   - *Технически:* хранить список каналов у проекта (новая модель, 1-к-многим с Conversation),
     периодически (крон/по заходу, с кэшем) тянуть их `uploads` + статистику. Квота умеренная, если
     кэшировать.
   - *Стоимость:* средняя (хранение + периодические вызовы Data API).

8. **«Ранняя тяга» / VPH на своих свежих видео.** 🔴
   - *vidIQ:* VPH — просмотры в час прямо сейчас; ловят моментум и делают ответный контент за 48ч.
   - *Наша адаптация:* на свежих роликах юзера считаем **раннюю скорость** (просмотры/подписки за
     первые часы-дни из daily-ряда) и, если «алгоритм пушит», действие: **«усиль, пока горячо»** —
     шортс из этого ролика (п.5), догоняющий ролик по теме, закреп. Если «глохнет рано» → «слабая
     упаковка/хук, разобрать».
   - *Технически:* из уже тянущегося `fetchDailyAnalytics` + `publishedAt`. Почти бесплатно.
   - *Стоимость:* низкая.

### Приоритет 3 — переосмыслить / опционально 🔴

9. **«Спрос на тему» (лёгкая версия Keyword Research, НЕ ядро).** 🔴/⛔-частично
   - *vidIQ:* search volume + competition + keyword score («золотые» слова: высокий спрос / низкая
     конкуренция).
   - *Наша адаптация (осторожно):* НЕ делаем SEO-центрированным. Максимум — **санити-чек темы**
     контент-плана: есть ли спрос/насколько забита ниша, как один из сигналов, а решение — по
     упаковке/ВИСП. Подавать как «проверка идеи», не как «подбор ключей». Честно помним: методика
     Велижанина про упаковку, а не про keyword-stuffing (см. §4).
   - *Стоимость:* средняя (нет прямого публичного API поиска-объёма от YouTube; либо оценка через
     autosuggest/косвенно, либо сторонний источник — обдумать отдельно).

10. **Генерация превью (аналог Thumbnail Maker).** 🟡→🔴
    - *vidIQ:* AI-картинка превью + A/B-тест по CTR.
    - *У нас:* **текст на превью по ВИСП** уже генерится в ИИ-разборе. Не хватает **картинки**.
    - *Опция:* генерация изображения превью (нужен image-модель/провайдер — отдельная стоимость и
      скоуп) + рекомендации по A/B (но CTR/показы публичный Analytics API не отдаёт — см. §4).
      Реалистичный шаг сейчас: **макет/раскадровка превью словами + ВИСП-текст**, картинку — позже.
    - *Стоимость:* высокая, если генерить изображения.

11. **Лучшее время публикации (Best Time to Post).** 🔴
    - Из данных аудитории/активности (частично уже тянем `fetchAudience`). Дёшево, но эффект
      скромный — низкий приоритет, «добить когда будет время».

12. **Трендовые алерты (Trend Alerts).** 🔴
    - Уведомление (пуш/письмо) «в твоей нише залетает X» — надстройка над «Разведкой залётов» (п.6).
      Нужна инфраструктура нотификаций.

13. **Свой MCP (аналог vidIQ MCP).** 🔴
    - vidIQ отдаёт данные канала во внешний Claude/ChatGPT. Для про-юзеров можем поднять **свой
      MCP-сервер** (данные канала + методика), чтобы тянуть в их Claude. Нишево, но сильный сигнал
      «мы инструмент, а не только чат». Далёкая перспектива.

## 4. Что сознательно НЕ берём (и почему) ⛔

- **SEO-score по тегам как ядро продукта.** vidIQ грейдит метаданные (кол-во тегов, «triple
  keywords» в title/tags/description). Методика Велижанина строит рост на **упаковке (превью/
  заголовок по ВИСП) и удержании**, а не на тегах. Копировать SEO-скоринг = уводить пользователя в
  ложную оптимизацию и ломать позиционирование. Теги как гигиену упомянуть можно, культ из них —
  нет.
- **Keyword-volume как основной способ выбора тем.** Берём только лёгкий «санити-чек спроса»
  (п.9); тему по-прежнему решает упаковка и Матрица, а не «объём ключа».
- **Полноценный видеоклиппинг** (обработка видеофайла). Вне скоупа/дорого. Заменяем на **таймкоды
  пиков удержания + сгенерированные хуки** (п.5) — тот же результат без видеопайплайна.
- **CTR/показы превью и их A/B.** Публичный YouTube Analytics API **не отдаёт** impressions/CTR
  (только Studio). Не обещаем то, чего API не даёт; используем прокси (доля «Рекомендованных»/
  «Обзора» из источников трафика) — уже есть на дашборде.
- **Instagram cross-platform** — не наш скоуп сейчас.

## 5. Технические заметки (заложить в оценку)

- **Квоты YouTube Data API.** `search.list` = **100 units/вызов**, дневная квота проекта по
  умолчанию **10 000 units** → «Разведка залётов»/«Конкуренты» упрутся в лимит быстро. Обязательно:
  серверный кэш, лимит вызовов на юзера, по возможности предрасчёт по нишам (а не на каждый клик).
  Возможно — запрос на повышение квоты в Google Cloud.
- **Analytics API ограничения** (уже знаем, см. [channel-analytics-plan.md](channel-analytics-plan.md)):
  нет CTR/impressions. Всё про удержание/подписчиков/аудиторию/трафик — есть.
- **Стоимость ИИ-действий = наша квота** (`Plan.limits.requests`, 1 действие = 1 единица). Каждая
  генеративная фича (аналитик-ассистент, ход дня, аудит, адаптация залёта, шортсы) должна ясно
  тратить квоту и кэшироваться где можно (особенно «ход дня» — кэш на сутки).
- **Проактивные фичи (ход дня, флаги, ранняя тяга)** — считать пороги/агрегаты **бесплатно** из
  уже собираемых метрик; тратить квоту только на генеративный шаг по действию юзера.
- **Переиспользуем существующее:** `buildSystem`/`buildFullSystem` ([system.ts](../src/lib/llm/system.ts))
  для голоса+методики; репорты YouTube ([youtube.ts](../src/lib/youtube.ts)); `recordStat` для
  телеметрии; движок глобальный (Claude/GLM/OpenRouter).
- **Image-модель для превью** (п.10) — отдельный провайдер и бюджет; не блокирует остальное.

## 6. Рекомендуемый порядок реализации

1. **Аналитик-ассистент** (P1.1) — быстрый видимый эффект, минимум инфраструктуры, прямо усиливает
   дифференциатор «аналитика → действие».
2. **Проактивные флаги на видео** (P1.4) — пороги бесплатны, кнопки ведут в уже готовый ИИ-разбор.
3. **«Ход дня»** (P1.2) — retention продукта; нужен кэш/крон.
4. **Автоаудит = колесо пиздатости** (P1.3) — виджет + генеративный разбор осей.
5. **Шортсы из пиков удержания** (P1.5) — надстройка над кривой удержания.
6. **Разведка залётов + конкуренты** (P2.6–7) — самая ценная разведка, но упирается в квоту API →
   делать после P1, с кэшем/лимитами.
7. Остальное (P2.8, P3) — по мере надобности.

> Принцип на каждом шаге: **берём механику vidIQ, отдаём результат в голосе Велижанина по КМК и
> сразу с действием**. Если фича не кормит петлю «аналитика/идея → готовый артефакт → действие» —
> она не про нас.
