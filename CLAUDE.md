Николая Велижанина на Claude API. Next.js 14 + TypeScript + Prisma + Mantine.

## Дорожная карта SaaS-составляющих

Легенда статусов: 🟢 готово · 🟡 в работе · 🔴 не начато

### Уже есть
- 🟢 **Лендинг: блок «Рабочий кабинет продюсера»** ([Workspace.tsx](src/components/Landing/Workspace.tsx),
  секция `#workspace` между `Features` и `Showcase`, пункт «Разделы» в `LandingNav`). Лендинг
  рассказывал только про чат, хотя вокруг него выросли разделы — блок ДОПОЛНЯЕТ страницу, а не
  переделывает её. Четыре карточки: аналитика канала, контент-план, генератор превью (с бейджем
  «бета»), дорожная карта и достижения; у каждой — абзац и три конкретных пункта.
  ⚠️ Скриншотов разделов пока НЕТ — вместо них иконка и текст. Пустые рамки-заглушки под будущие
  картинки не ставим: пустая рамка на лендинге читается как недоделка. Появятся снимки — менять
  только визуал карточки, сетка и текст останутся.
  ⚠️ Описание карточки НЕ `c="dimmed"`: замерили в браузере — приглушённый токен на этой подложке
  даёт ~4:1, ниже нормы 4.5:1. С основным цветом 9.37:1. Проверено также, что на 375px карточки в
  одну колонку и горизонтального скролла нет.
- 🟢 **Лендинг** — брендовый продающий лендинг + дизайн-система velizhanin.com
  (акцент `#EC582E`, шрифт RandomGrotesque). `src/app/page.tsx`, `docs/design-system.md`.
- 🟢 **Чат с AI-ассистентом** — `POST /api/chat` (стриминг, prompt caching).
  `src/app/chat/page.tsx`, `src/app/api/chat/route.ts`. Ответы рендерятся как
  **markdown** (`components/Chat/Markdown.tsx`, react-markdown + remark-gfm; стили
  `.md-body` в globals.css). **Блок-цитаты** (готовые к произнесению фразы: хук, реплика,
  текст на превью) рендерятся кастомным компонентом `Blockquote` — уменьшенный кегль
  (`0.8125rem`, Mantine по умолчанию делает их крупными) + кнопка «копировать» в углу
  (`.md-quote-copy`, проявляется на hover/focus, на тач-устройствах видна всегда; копирует
  `innerText` цитаты, иконка `IconCopy`→`IconCheck` на 1.5с). Свои сообщения вправо, баббл по контенту. Бабблы —
  токен-ориентированные классы `.bubble-user` / `.bubble-assistant` (контраст ≥4.5:1
  в обеих темах; свои — оранжевый тинт бренда + обычный текст, ответы — нейтральная
  поверхность gray.1 / dark.6 с видимым бордером).
  - 🟡 **«Борода» под ответом ассистента** — [MessageFooter.tsx](src/components/Chat/MessageFooter.tsx):
    слева время ответа (сегодняшние — только `ЧЧ:ММ`, старые — `5 авг, 14:20`), справа кнопка
    **«Копировать»** (иконка `IconCopy`→`IconCheck` на 1.5с, как у цитат). **Не протестировано
    вживую** (локально не поднимается БД). Зачем: выделить мышкой длинный сценарий целиком в
    скроллящейся ленте практически невозможно — на этом и споткнулись пользователи.
    - Копируется **исходный markdown** (`parsed.text`, маркер `[[connect_youtube]]` уже вырезан),
      а НЕ отрисованный `innerText`: заголовки, жирный и списки переживают вставку в редактор.
      У блок-цитат наоборот — там `innerText`, потому что цитату произносят вслух.
    - Полоса **прижата к краям баббла**: отрицательные `margin` гасят `padding` у `Paper p="sm"`
      (`.msg-foot` в globals.css). Фона нет, только линия сверху — поэтому скруглённые углы
      баббла ничем перекрывать не надо.
    - Только у ОТВЕТОВ и только у сохранённых сообщений: на стриминговом баббле бороды нет
      (там ещё нет ни даты, ни финального текста) — она появляется, когда ответ дописан.
  - **Плавная «печать» ответа** (`makeTypewriter` в `ChatInput.tsx`): модель отдаёт
    дельты рвано, поэтому копим их в буфер и раскрываем в стор (`appendStreamingContent`)
    с постоянной частотой ~30fps (`setInterval`, `TYPE_TICK_MS`) адаптивным шагом
    (малое отставание → 2 симв/кадр, большое → ~1/8 остатка, чтобы догнать «убежавший»
    стрим без рывка). После конца стрима — `typewriter.end()` допечатывает хвост, потом
    `finalizeStreaming`+`addMessage`. Ошибка → `typewriter.cancel()` (таймер не висит).
    Уважает `prefers-reduced-motion` (там текст появляется сразу). 30fps вместо 60 — вдвое
    меньше ререндеров markdown (`streamingContent` парсится react-markdown на каждый кадр).
    Мигающая **каретка** в конце печатаемого текста: проп `streaming` у `Markdown` вешает
    класс `.md-streaming`, CSS-каретка `▊` через `::after` на последнем блоке (globals.css,
    бренд-цвет, анимация `blink`; гасится при `prefers-reduced-motion`). Только на живом
    баббле; в состоянии ожидания первого токена — индикатор «думаю» (см. ниже).
  - **Индикатор «думаю» (маскируем долгий TTFT)** — `components/Chat/ThinkingIndicator.tsx`.
    TTFT у нас большой (не из-за размера контекста — проверяли), поэтому вместо статичного
    «печатает▊» до первого токена крутим живые статусы в голосе Велижанина («врубаюсь в
    вопрос» → «прикидываю, как лучше зайти» → «собираю мысли» → «накидываю структуру» →
    «пишу ответ»). Цепочка `setTimeout` по индексу (шаг 1.9с), на последней фразе
    останавливаемся (не зацикливаем в начало — иначе кажется, что снова «врубается»). Текст —
    приглушённый с бегущим бренд-бликом (`background-clip:text` + анимация `thinking-shimmer`),
    смена фразы — fade-in снизу (`thinking-in`, ремоунт по `key={i}`), рядом стаггер-пульс
    точек (`thinking-dot`). Всё гасится при `prefers-reduced-motion` (статичный dimmed-текст).
    ⚠️ Классы называются `thinking-*` НЕ случайно: префикс `ti-*` коллизит с Tabler Icons
    (шрифт иконок) — между текстом и точками подмешивался левый глиф-«звёздочка». Не
    переименовывай в `ti-*`.
    Стили `.thinking-*` в globals.css; рендерится в `ChatWindow` при `isLoading &&
    !streamingContent`. Как пойдёт текст — индикатор сменяется живым бабблом с кареткой.
  - **Без карточки-обводки:** сообщения «текут» по фону страницы (раньше была
    `Paper withBorder` — на тёмной давала резкую серую рамку). Композер (поле ввода +
    «отправить») — отдельный мягкий блок `.chat-composer`: скруглённая поверхность
    (gray-0 / dark-6, без бордера), `Textarea variant="unstyled"` сливается с ней,
    фокус — `outline` бренд-акцента на `:focus-within`. По «Новый чат» фокус прыгает
    в поле через `inputFocusSignal` (тик в `chatSlice`, слушает `ChatInput`).
  - **Черновик ввода:** недоотправленный текст пишется в localStorage по debounce
    (400 мс), ключ `creative-chat:chat-draft-v1` (scoped по `userId`). Восстанавливается
    при заходе на /chat (не затирая уже начатый ввод), удаляется при отправке. Всё в
    `ChatInput.tsx`.
  - **Готовые запросы («что я умею») — в ДВУХ местах, список один.** Источник —
    [suggestions.tsx](src/components/Chat/suggestions.tsx) (`SUGGESTIONS`: иконка + заголовок +
    prompt; формулировки под категории роутера знаний, часть промптов намеренно обрывается
    двоеточием — юзер дописывает тему). Клик подставляет текст в композер через
    `chatSlice.prefillInput` (тик `seq` → `ChatInput` кладёт в поле). Потребители:
    **(1)** плитки стартового экрана пустого чата ([ChatWelcome.tsx](src/components/Chat/ChatWelcome.tsx),
    `SimpleGrid`) и **(2)** **лента быстрых действий НАД полем ввода**
    ([QuickActions.tsx](src/components/Chat/QuickActions.tsx)) — те же запросы компактными
    чипами в одну строку с горизонтальным скроллом и круглыми стрелками ‹ › по краям.
    Лента нужна, потому что после первого сообщения стартовый экран пропадает и функционал
    иначе становится недоступен; при исчерпанном доступе (`locked`) не рендерится — там CTA
    на тариф. Собрана на **Mantine** (`ScrollArea type="never" scrollbars="x"` + `Group
    wrap="nowrap"` + `Button variant="default" radius="xl"`) — тот же паттерн, что у
    горизонтальной ленты вкладок в `TopNav`; своего CSS остался только `.qa-arrow`
    (позиционирование стрелок поверх ленты). Грабли, на которые уже наступали:
    • **`wrap="nowrap"` обязателен** — с переносом чипов горизонтального overflow не
    возникает вовсе, лента не скроллится, а стрелки (центр по высоте обёртки) съезжают вниз
    между строк; • **ширину контента меряем по ряду чипов** (`row.scrollWidth`), а НЕ по
    `scrollWidth` вьюпорта: тот включает боковой padding, который сам зависит от наличия
    стрелок → петля «стрелка появилась → шире padding → влезло → стрелка исчезла → …»;
    • боковой padding переключается 34px/4px **отдельно по каждому краю** — по факту
    ВИДИМОСТИ своей стрелки, а не общего переполнения (иначе слева зияет пустота, пока лента
    стоит в начале и левой стрелки ещё нет); • **стрелку позиционирует ОБЁРТКА `Box.qa-arrow`,
    а не сам `ActionIcon`**: у Mantine-кнопок есть `:active { transform: translateY(...) }`,
    который затирает центрирующий `translateY(-50%)` — на нажатии стрелка проваливалась вниз;
    • у `.qa-arrow` `z-index:10`, иначе клик по стрелке проходит на чип под ней; • стрелки
    **скрываются** у края, а не дизейблятся (неактивная кнопка вплотную к композеру —
    визуальный шум); края
    пересчитываются на скролле и через `ResizeObserver` (ширина меняется и при сворачивании
    сайдбара), допуск 1px против дробных subpixel-ширин; • **колесо/вертикальный жест
    тачпада листают ленту вбок** — слушатель `wheel` вешается вручную с `{passive:false}`
    (React-овый `onWheel` пассивный, `preventDefault` из него не сработает); горизонтальный
    жест (`deltaX`) не перехватываем — его отрабатывает браузер.
  - **Мобильная раскладка (flex по высоте вьюпорта):** `AppShell.Main` фиксирован на
    `height:100dvh`, внутри — flex-колонка (`maw 900`): титл/алерты сверху, `ChatWindow`
    (ScrollArea) тянется `flex:1` и скроллится сам, `ChatInput` прижат снизу. Так
    **страница целиком НЕ скроллится** (титл не уезжает), скроллятся только сообщения
    (ушли от хрупкого `calc(100vh - 260px)`). Клавиатура: `viewport.interactiveWidget =
    "resizes-content"` (`app/layout.tsx`) → на Android контент сжимается, поле ввода
    остаётся над клавиатурой, верх виден; `dvh` учитывает адресную строку. На мобиле
    меньше боковые отступы (`AppShell padding` + `ChatWindow`/`ChatInput` — `{base, sm}`)
    и мельче титл (`fz={{base:"1.35rem", sm:"1.75rem"}}`).
    - **Бабблы во всю ширину на мобиле** (`ChatWindow.tsx`): на десктопе баббл ограничен
      `maw 78%` и слева/справа аватар (`ThemeIcon`), а на мобиле аватары скрыты
      (`visibleFrom="sm"`) и баббл тянется на всю ширину (`maw={{ base:"100%", sm:"78%" }}`)
      — иначе на узком экране длинный текст жался в тонкую колонку. Десктоп не тронут.
      У `ScrollArea` убран `offsetScrollbars` (он резервировал место под скроллбар
      только справа → правый край бабблов не совпадал с полем ввода); теперь скроллбар —
      оверлей, а лента и `ChatInput` имеют одинаковый `px={{base:4,sm:"md"}}` → края ровно
      совпадают.
  - **Брейкпоинт мобильного вида — `lg` (1200px):** бургер + сайдбар-оверлей держим
    вплоть до iPad (телефоны и планшеты в обеих ориентациях), постоянный сайдбар — только
    на десктопе (≥1200). Все `hiddenFrom`/`visibleFrom`/`Burger` в `AppShell` синхронны с `lg`.
  - **Дисциплина вывода + лимит артефактов за ответ** (`OUTPUT_DISCIPLINE` в
    `route.ts`, добавляется в system на генеративных запросах `route.category !== "chat"`,
    для обоих движков). Ответ — сразу артефакт, без преамбул/резюме, рубленым стилем.
    **Жёсткий потолок: не больше 4 полных сценариев / контент-планов за один ответ**,
    сколько бы ни просили (хоть 50). Если просят больше — модель живой фразой говорит, что
    за раз больше 4 не делает, выдаёт до 4 доведённых до конца штук и спрашивает
    «Продолжаю?» (помня, на чём остановилась). Лёгкие артефакты (хуки, названия, темы,
    короткие идеи) под лимит 4 НЕ попадают — до 7 за ответ. Задача от команды: срезать
    «простыни» из десятков сценариев.
  - **Качество grounding без роста стоимости** (рычаги «качество вверх, токены те же»):
    - **Ретрив (книга/TG) — в самом КОНЦЕ system, вплотную к вопросу** (`buildSystem`
      в `route.ts`). Это блоки «мои формулировки, копируй дословно», а модель сильнее
      весит последнее перед вопросом (recency). Раньше шли в середине (перед брифом/«о
      себе») — модель хуже копировала. Все они некэшируемые, поэтому перестановка внутри
      хвоста ЦЕНУ не меняет и кэш-префикс (хребет + форматы) не ломает.
    - **Слой YouTube-транскриптов** ([knowledge-base-youtube.ts](src/lib/knowledge-base-youtube.ts))
      — курированная выжимка из расшифровок ~25 роликов с YouTube-канала Велижанина
      (живой разговорный слой поверх книги/TG). Разбор воронки охватов и расширения ниши,
      лестницы Ханта, Матрицы бесконечного контента, названий/SEO, превью, удержания,
      сценария, харизмы/образов спикера, аналитики (7 параметров), шортсов (совмещение с
      лонгами), проявленности/самозванца, речи на камеру + стратегии по нишам (b2b,
      строительство, психология, недвижимость, подкасты, тревел) с кучей реальных кейсов
      студии. Подключён как **BM25-ретрив** (`buildYoutubeContextBlock` в
      [knowledge-retrieval.ts](src/lib/knowledge-retrieval.ts), тот же чанкинг/бюджет ~30k
      символов, что у TG) на **все не-chat запросы** (`RouteDecision.youtube`, ставится в
      `mapCategory` для short/long/method/content_plan; в edit-followup — off, как книга) и
      **целиком в full-режиме** (`buildFullSystem`). В хвосте `buildSystem` идёт между
      открытым TG и книгой. Самый широкий слой — держит кейсы и разговорные разборы, которых
      нет в книге/TG. Голосовые фразы из роликов разнесены в `VOICE_SAMPLES`
      ([knowledge-base-voice.ts](src/lib/knowledge-base-voice.ts), секция «Как звучу в
      разборах на YouTube»). Пополнять — курированной выжимкой по темам (не сырой ASR),
      сохраняя дословные формулировки/кейсы.
      - **Пополнение из 440 транскрипций закрытого клуба КМК «Контент Могущество»** (2026-07,

      докам. Сравнение с `"SHORTS"` молча не срабатывало, и **весь трафик шортсов уезжал в
      «обычные видео»** сразу в трёх местах (графики, `fetchContentSplit`, разбор канала по 7
      параметрам). Нормализация теперь одна на всех — **`contentTypeOf`** в
      [youtube.ts](src/lib/youtube.ts); `unspecified` в срезы не идёт (это не контент, а хвост
      без привязки — обычно подписчики не с видео), но в итог по каналу попадает.

      очередью, до «подробностей»). Зачем отдельно: у шортсов и лонгов разная природа охвата,

- 🟢 **Фикс «белого экрана» в Safari < 16.4 (lookbehind в remark-gfm).** У части
  пользователей чат не грузился: в консоли `SyntaxError: Invalid regular expression:
  invalid group specifier name` + `ChunkLoadError` + Minified React error #423, и как
  следствие — сайдбар «Мои проекты» висел вечным лоадером (JS чанка не исполнялся, эффект
  загрузки в `AppShell` не отрабатывал). Причина НЕ в кэше/деплое/Caddy: `remark-gfm@4`
  (рендер markdown в `components/Chat/Markdown.tsx`, на каждом кадре стрима) тянет
  `mdast-util-gfm-autolink-literal@2.0.1`, где regex автолинка email использует
  **lookbehind** `(?<=^|\s|\p{P}|\p{S})`. Safari добавил lookbehind только в 16.4 — на
  старых iOS/macOS Safari regex-литерал кидает SyntaxError при разборе модуля → весь чанк
  markdown падает → рушится React-дерево → не грузится UI.
  - **Решение — `patch-package`** (`patches/mdast-util-gfm-autolink-literal+2.0.1.patch`):
    убираем lookbehind, regex становится `/([-.\w+]+)@([-\w]+(?:\.[-\w]+)+)/gu`. Поведение
    сохраняется: граница перед адресом и так перепроверяется в `findEmail` через
    `previous(match, true)` по `match.index` (lookbehind нулевой ширины — `match.index` не
    меняется). Проверено сравнением старого/нового regex на наборе строк (включая
    символ/эмодзи перед адресом) — наборы принятых адресов идентичны.
  - **Применение патча:** скрипт `postinstall: patch-package` в `package.json`
    (devDep `patch-package`). В Dockerfile deps-стадия копирует `patches/` ДО `npm ci`
    (иначе postinstall тихо ничего не пропатчит). Это единственный клиентский lookbehind в
    бандле (проверено grep'ом по node_modules) — других Safari-несовместимых regex нет.

## Качество ИДЕЙ: почему были «средние по интернету» и что починили (2026-08-07)

🟡 **Жалоба «идеи слишком иишные и неживые» оказалась не про промпт, а про ПОДАЧУ КОНТЕКСТА.**
Разбор показал: модель физически не видела ни слоя методики про названия, ни фактуры клиента.
Починено пятью правками, ни одна не стоит токенов сверху (кроме банка триггеров, ~3k).

- 🟢 **Баг: `content_plan` от роутера выбрасывался всегда.** [router.ts](src/lib/router.ts) нормализовал
  ответ классификатора как `.replace(/[^a-z]/g, "")` — подчёркивание срезалось, `content_plan`
  превращался в `contentplan`, не проходил `VALID.includes` и МОЛЧА откатывался на грубую
  keyword-эвристику. Теперь `/[^a-z_]/g`.
- 🟢 **Баг: генератор контент-планов искал по захардкоженной константе.** В
  [content-plan-server.ts](src/lib/content-plan-server.ts) `routeHint` был строковой константой, и
  она же уходила в BM25. Ретрив — чистая функция от запроса, поэтому **все клиенты получали
  побайтово одинаковую фактуру**: из 15 нишевых шпаргалок доезжали одни и те же три (авто, финансы,
  недвижимость). Теперь `routeHint` собирается из брифа; туда же прокинут снимок канала
  (`resolveChannelBlock`, best-effort) — модель видит, что у клиента реально залетало.
- 🟢 **Бриф не участвовал в поиске по базе.** `searchQuery` = ключевые слова роутера + текст
  вопроса, а роутер по инструкции подмешивает ТЕРМИНЫ МЕТОДИКИ. Ниша клиента в запрос не попадала
  вообще. Появились `briefSearchTerms` / `withBriefTerms` ([brief.ts](src/lib/brief.ts)), применены
  во всех пяти точках сборки промпта (чат, контент-план ×2, превью-спека, разбор видео).
  **Замерено прогоном ретрива:** с брифом в выдачу приходят «Нишевые инсайты», «Как искать темы для
  контента», «Банк реальных залетевших названий», а уходят нерелевантные «Дизайн превью» и «SEO».
- 🟢 **Категория `long` не грузила слой упаковки.** `mapCategory` для `long`/`method` возвращал
  только `{book, youtube}` — то есть на «напиши сценарий» и «придумай названия» **весь закрытый TG
  (банк слов ВИСП, порядок сборки названия, слабые слова под нож, банк залетевших названий, а также
  7-шаговая структура сценария) не подключался вообще**. Теперь `tgClosed: true`. Слой режется
  бюджетом ретрива (~30k символов), промпт не взрывается.
- 🟢 **Новая категория роутера `ideas`** — «придумай темы / идеи / названия / текст на превью» без
  полного сценария и без месячной сетки. Раньше такие запросы падали в `long`. Слои: книга +
  закрытый TG + YouTube, **без** эталона контент-плана (иначе ответ уезжает в формат таблицы).
  Все потребители `route.category` сравнивают только с `"chat"`, поэтому новая категория ничего не
  ломает. Прогнано на 10 живых формулировках.
- 🟢 **Банк триггеров — [knowledge-base-triggers.ts](src/lib/knowledge-base-triggers.ts)**
  (`TRIGGER_BANK`, ~9k символов). 16 позиций флипчарта Велижанина, собранные из мест, где они были

закрывал только «энциклопедическую» фактуру, и его список был ЗАКРЫТЫМ: фильмы, имена, эксперименты,

именно болячки — фактура клиента. Тест: автор может проверить это утверждение по своей практике и
поймать нас на вранье? Тогда не пишем — оставляем место в каркасе и просим ОДНИМ конкретным вопросом.

- **Антипаттерн №9** ([knowledge-base-antipatterns.ts](src/lib/knowledge-base-antipatterns.ts)) —

- **`SYSTEM_CORE`** ([system.ts](src/lib/llm/system.ts)) — пункт 6 в алгоритме grounding

  ретривом — то есть правило про фактуру оставалось в середине промпта и тонуло. Теперь на

## Веб-поиск в чате (OpenRouter web-плагин) — 2026-08-10

🟡 **Модель может искать в интернете перед ответом. Выключено по умолчанию, включается в
`/admin/flags`. Не протестировано вживую** (нужен прод с включённым флагом).

Зачем: второй слой к guard'у выше — свежая фактура и меньше шансов, что модель подставит
«самое частое из интернета» вместо реального факта. ⚠️ Guard при этом НЕ отменяется: поиск даёт
доступ к фактуре, но не даёт дисциплину — без правил из Антипаттерна №9 модель просто найдёт
подтверждение своей выдумке.

- **Реализация — плагин OpenRouter** (`plugins: [{ id: "web", max_results: N }]` в теле запроса,
  [openrouter.ts](src/lib/llm/openrouter.ts)), а НЕ серверный `web_search` Anthropic: рабочий движок
  — DeepSeek через OpenRouter. Claude/GLM параметр игнорируют (`StreamArgs.webSearch`).
- ⚠️ **Кэш промпта плагин НЕ ломает — проверено замером** (скрипт-проба на `deepseek/deepseek-v4-pro`
  с пином провайдера): с плагином `cached_tokens` 13135 из 14520 (90%), без него 11406 из 12412.
  Выдача подмешивается ПОСЛЕ кэшируемого префикса, поэтому full-режим на DeepSeek не страдает.
  Это был главный риск, и он снят — переизмерять при каждой правде не нужно, но при смене модели или
  провайдера стоит перепроверить тем же способом (`prompt_tokens_details.cached_tokens` в usage).
- ⚠️ **Платно ОТДЕЛЬНО от токенов: замерено ~$0.004 за результат.** Тот же запрос: без плагина
  $0.0009–0.0019, с двумя результатами $0.008. При `max_results: 3` это **+$0,012 к каждому
  запросу** — сопоставимо со стоимостью самой генерации. Поэтому дефолт `enabled: false`, потолок
  результатов 1–5 (`normalizeWebSearch` в [settings.ts](src/lib/settings.ts)), и поиск НЕ тратится
  на болтовню (`route.category === "chat"` — «привет», «спасибо»).
- **Настройка** — `AppSettings.webSearch { enabled, maxResults }` (ключ `AppSetting` = `web_search`),
  тумблер + число результатов в `/admin/flags` в карточке движка (видно только при OpenRouter),
  валидация в `PATCH /api/admin/settings`.
- **Индикатор «Ищу в интернете»** — поиск заметно добавляет к TTFT, который у нас и так больной, без
  подписи это читается как «завис». `route.ts` шлёт отдельное SSE-событие `{searching:true}` ДО
  начала генерации (не токен — до первого токена стрим и так молчит), `ChatInput` кладёт его в
  `chatSlice.isSearching`, [ThinkingIndicator](src/components/Chat/ThinkingIndicator.tsx) переключает
  цепочку фраз на «ищу в интернете → смотрю, что пишут → сверяю фактуру → …» и рисует пульсирующий
  глобус (`.thinking-globe` в globals.css, гасится при `prefers-reduced-motion`).
  ⚠️ Сигнал приходит асинхронно, поэтому индикатор **сбрасывает индекс фразы в 0** при получении —
  иначе «ищу в интернете» проскочило бы мимо, если цепечка уже шагнула вперёд. `setLoading(false)`
  гасит флаг, иначе следующий ответ открылся бы с «Ищу в интернете» без поиска.
  ⚠️ Класс `thinking-globe`, НЕ `ti-*` — префикс `ti-*` коллизит с Tabler Icons (см. выше).

## Пробный период: срок в админке + массовый сброс (2026-08-10)

🟡 Две ручки, которые НЕ путать: **срок** пробного периода — `AppSettings.trialHours`
(`/admin/flags`, ключ `trial_hours`, кламп 1–168 ч), **число запросов** — `Plan.limits.requests`
бесплатного тарифа (редактор тарифов). Раньше срок был константой `TRIAL_DURATION_MS` = 1 час.
`trialExpiresAt(hours?)` теперь принимает часы; регистрация и OAuth читают их из настроек.
**Не протестировано вживую** (кнопку нажимал только через выборку, без записи).

**Массовый сброс** — `GET|POST /api/admin/trial-reset` + кнопка «Открыть пробный период заново»
в карточке «Пробный период». Нужен перед рассылкой: человек приходит по письму, и у него снова
есть доступ.

⚠️⚠️ **Выдача ПЕРСОНАЛЬНАЯ, а не разовым `updateMany` — не «упрощай» обратно.** Кнопка ставит
только МЕТКУ времени (`AppSettings.trialResetAt`, ключ `trial_reset_at`), а сам период выдаётся
каждому при ЕГО первом заходе после метки — `maybeGrantTrial` ([quota.ts](src/lib/quota.ts)),
вызывается из `getSessionUser` ([auth.ts](src/lib/auth.ts)).
Почему: при разовом обнулении срок отсчитывался бы от нажатия кнопки. Нажали в 11:00 при сроке
3 часа — в 14:00 у всех истекло, и человек, открывший письмо в 15:00, упирается в закрытую дверь,
хотя ему только что написали «доступ открыт». С меткой он получает свои полные 3 часа в 15:00.

- **Маркер выдачи — `User.trialGrantedAt`** (миграция `add_trial_grant`). Условие: выдать, если
  `trialGrantedAt` пуст или СТАРШЕ метки. После выдачи `trialGrantedAt = now` > метки, поэтому
  повторно не сработает, сколько бы страниц человек ни открыл.
  ⚠️ Отдельная колонка нужна именно потому, что вывести факт выдачи из `planExpiresAt` нельзя:
  у легаси-юзеров он `null`, и без маркера им обнуляло бы квоту на каждом запросе.
- **Выдача сбрасывает ОБЕ границы**: `planExpiresAt = now + trialHours` и `requestsUsed = 0`.
  Только срок мало — у человека с исчерпанной квотой доступа всё равно не будет.
- ⚠️ **Кого не трогает:** тех, у кого есть платёж `CONFIRMED`, и тех, кто на ПЛАТНОМ тарифе
  (`priceRub > 0`) даже без платежа в базе — такой тариф мог быть выдан руками из админки.
- ⚠️ **Пробным считается любой тариф с `priceRub === 0`**, включая архивный.
- ⚠️ **Легаси-юзерам с `planExpiresAt = null` выдача ДОБАВИТ срок** (сейчас у них ограничения по
  времени нет). Это ужесточение — если такие в базе есть, решать осознанно.
- **Горячий путь дешёвый:** у кого пробный уже выдан после метки, `maybeGrantTrial` выходит на
  первой проверке — ни одного лишнего запроса к БД.
- `GET` отдаёт число тех, кого метка затронет — админ видит масштаб до нажатия.

## Фоновые задачи (очередь на Postgres, без брокера) — 2026-08-10

🟡 **Долгие операции вынесены из http-запроса в очередь: обновление страницы или уход больше не
убивают результат.** Повод — на проде теряли и генерацию превью, и контент-план. Модель `Job`
(миграция `add_jobs`), ядро — [jobs-server.ts](src/lib/jobs-server.ts), воркер —
[worker.ts](src/lib/worker.ts), API `/api/jobs` + `/api/jobs/[id]`, клиент —
[jobs-client.ts](src/lib/jobs-client.ts). **Не протестировано на живой генерации.**

⚠️ **Брокера (RabbitMQ) сознательно НЕТ.** Результат всё равно надо хранить в БД, инстанс один, а
`FOR UPDATE SKIP LOCKED` тянет тысячи задач в минуту — на порядки выше нашей нагрузки. Когда
инстансов станет несколько, меняется только `claimJob()`; API и клиент не трогаются.

⚠️ **Воркер стартует ЛЕНИВО из node-роутов (`ensureWorker`), а НЕ из `instrumentation.ts`.** Пробовали
через instrumentation — Next компилирует его и под edge-рантайм, и хотя запуск закрыт проверкой
`NEXT_RUNTIME`, сборщик всё равно трассирует импорт обработчиков и падает на node-модулях
(`Can't resolve 'fs' / 'crypto'`), роняя страницы в 500. Не возвращай instrumentation.
⚠️ По той же причине обработчики не должны тянуть модули с сессией: `toRow`/`spendQuota` вынесены в
[thumbnails-row.ts](src/lib/thumbnails-row.ts), `isAdmin` — в [admin-role.ts](src/lib/admin-role.ts)
(старые импорты работают через реэкспорт).

- **Переведено:** генерация превью (`thumbnail_generate`), контент-план (`content_plan_generate`),
  опорные блоки плана (`content_plan_block`), разбор канала (`channel_diagnose`).
  ⚠️ Логика разбора канала вынесена из роута в [channel-diagnose-server.ts](src/lib/channel-diagnose-server.ts)
  (`runChannelDiagnose` + промпт-хелперы): роут остался тонким гейтом, воркеру сессия не нужна.
  Ошибки протухшего доступа к YouTube отличает `isReauthError` — клиент по нему просит переподключить.
- **Переведён и разбор видео** (`video_analyze`): логика вынесена в
  [video-analyze-server.ts](src/lib/video-analyze-server.ts) (`runVideoAnalyze`), роут — тонкий гейт.
  ⚠️ Проверку «YouTube подключён» оставили В РОУТЕ: так пользователь видит ошибку сразу, а не через
  минуту в упавшей задаче. Бриф читает уже обработчик — роуту он не нужен.
  ⚠️ Дубль ловим по videoId: `findRunningJob` отдаёт идущую задачу только если это тот же ролик —
  разбирать РАЗНЫЕ ролики параллельно нормально, в отличие от генерации плана или превью.
- 🟢 **Цепочка задач:** после успешной сборки контент-плана воркер САМ ставит задачи на опорные
  блоки (портреты ЦА, лестница Ханта, сетка шортсов) — раньше человек жал «Собрать» на каждом
  вручную. Ставятся отдельными задачами, а не считаются в том же обработчике: так каждый блок виден
  своим статусом, падение одного не роняет остальные, и повтор работает поблочно.
- **Защита от дублей:** `findRunningJob` — двойной клик или ретрай после перезагрузки отдают ту же
  задачу, а не ставят вторую (генерация превью стоит 10 единиц квоты, план — 25).
- **Квота списывается в обработчике и только после успеха** — упавшая задача бесплатна.
- Незавершённые задачи страница подхватывает через `GET /api/jobs?projectId=&kind=`; id последней
  задачи дублируется в localStorage только для ускорения первого кадра.
- Рубильник `JOBS_WORKER=off` в env — выключить воркер (если позже вынесем в отдельный контейнер).
- ⚠️ **`FatalJobError` — сбой БЕЗ повторной попытки.** Нужен там, где работа уже оплачена
  провайдеру, а упал только «хвост»: генерация превью падала на `saveUpload` (EACCES на папке
  загрузок), задача уходила в ретрай и **рисовала картинку заново за новые деньги** (~$0.14 за
  попытку). Теперь сбой записи файла помечается окончательным: пользователь нажмёт сам, когда
  причина устранена. Бросать этот класс ошибок стоит везде, где повтор = повторная оплата.

## Пунктуация: у названия и у картинки РАЗНЫЕ правила (2026-08-10)

🟡 **Не путать (уже ошибались):**
- **Текст НА КАРТИНКЕ — знаков нет вообще**, включая «?», «!», «|», «/». Только слова. На мелкой
  обложке в ленте любой знак читается как грязь и отъедает кегль у главного слова.
- **В НАЗВАНИИ ролика разрешены «.», «?», «!», «|», «/»** — ими и режется мысль. Запрещены только
  запятые, двоеточия, точки с запятой, тире-разделители, кавычки, скобки, многоточия.

**Не протестировано на живой генерации.**

⚠️ **Чистка НА ВХОДЕ, а не просьбой в промпте** — `stripThumbTextPunctuation` /
`stripTitlePunctuation` в [thumbnails.ts](src/lib/thumbnails.ts), применяются в `sanitizeSpec`.
Причина: image-модель рисует ровно те символы, что мы дали между `[TEXT]…[/TEXT]`, и «не рисуй
запятую» она нарушит именно тогда, когда запятая есть во входе. Чиним вход.
⚠️ **Дефис в классы символов НЕ ставим** — он нужен внутри слов («из-за», «онлайн-курс»).
Тире-разделитель убирается отдельным `DASH_SEPARATOR` (только когда окружено пробелами). На этом уже
спотыкались: «из-за» превращалось в «из за».
⚠️ Антипаттерн №4 раньше явно разрешал «внутри свободно: запятая, тире, двоеточие» — переписан.
Эталоны там приведены к виду без запятых; исторический «Банк залетевших названий» в `tg-closed.ts`
не трогали (живые названия), но пометили оговоркой.

Живёт в пяти местах, держи согласованными: `SYSTEM_CORE` (блок «Пунктуация: у названия и у картинки
РАЗНЫЕ правила»), `FINAL_CHECKLIST`, Антипаттерн №4

## Контракт голоса: синтаксис нейросети (Антипаттерн №14)

🟡 **Борьба с «иишностью» на уровне СИНТАКСИСА, а не содержания.** До 2026-08-07 все 13 антипаттернов
(66 КБ) были про содержание — и ни одного про конструкции, по которым текст палится за две секунды.
Поводом стала жалоба «идеи слишком иишные и неживые» с живым примером из прода (проект «Бизнес
психология»): *«Ты не коуч — ты диагност. Твой зритель — не пациент, а партнёр»* + *«факты, цифры,
жёсткая подача»* + *«Хочешь следующий сценарий… Или сразу под это сделаем превью?»*.
Запрещены три тика: **антитеза «не X — а Y»** (и «не просто X, а Y», «это не X, это Y»), **триада**
(три однородных куска подряд — перечисления делаем рваными, два или четыре, разной длины) и
**вежливый хвост с меню** («Хочешь A? Или сразу B?» → одно следующее действие одной фразой).
Плюс пустые формулы «Слабость тут одна…», «Главное тут одно…», «Секрет прост…».
Живёт в [knowledge-base-antipatterns.ts](src/lib/knowledge-base-antipatterns.ts) (Антипаттерн №14,
с таблицей перевода) и продублировано строкой в `FINAL_CHECKLIST`
([system.ts](src/lib/llm/system.ts)) — иначе на длинном контексте правило тонет в середине.
⚠️ Не путать с «убрать мат»: тут меняется только синтаксис, дерзость и напор остаются.

## Переключатель модели (Claude / GLM / OpenRouter) — ГЛОБАЛЬНЫЙ, из админки
- 🟢 **Стратегии провайдера** — `src/lib/llm/`: `types.ts` (интерфейс `LlmStrategy` +
  тип `LlmProvider`), `claude.ts` (Anthropic SDK: модель/effort/кэш/лог стоимости),
  `glm.ts` (fetch на OpenAI-совместимый `/chat/completions`, парсинг SSE, склейка
  system-блоков Anthropic в один system-месседж), `index.ts` (`getStrategy` /
  `normalizeProvider`). Обе стратегии отдают текстовые дельты — `route.ts` оборачивает их
  в SSE одинаково. `route.ts` больше не знает про конкретного провайдера: собирает system,
  роутит знания, выбирает стратегию по **глобальной настройке** (`settings.provider`).
- 🟢 **Стоимость в логах** — каждая стратегия логирует свою строку `[chat] provider=…`.
  Claude — по тарифам Opus (вход/выход/кэш). GLM — по `usage` из последнего чанка стрима
  (`prompt_tokens`, `completion_tokens`, `prompt_tokens_details.cached_tokens`): кэш у GLM
  **автоматический** (implicit, `cache_control`/ttl не нужны и игнорируются), попадания
  считаем по льготному тарифу. Тарифы GLM — константы в `glm.ts` (как тарифы Opus в
  `claude.ts`); под GLM-5.2 (вход $1.4 / выход $4.4 / кэш $0.26 за 1M).
- 🟢 **Фикс «плоских» ответов GLM/DeepSeek (markdown-форматирование).** Общий system-промпт
  просит «связные абзацы, не простыни-буллеты» (голос Велижанина). Claude балансирует
  структуру и живую речь сам, а GLM И DeepSeek (обе — через OpenAI-совместимый стрим)
  понимают установку буквально → монолитные ответы
  без выделений/иерархии, особенно на тематических/разборных запросах. Решение —
  общая константа `MARKDOWN_FORMATTING` в [src/lib/llm/formatting.ts](src/lib/llm/formatting.ts),
  дописывается в КОНЕЦ system-месседжа **и в `glm.ts`, и в `openrouter.ts`** (`systemText`;
  раньше жила инлайном в `glm.ts` как `GLM_FORMATTING` и на DeepSeek не действовала — отсюда
  «plain» ответы OpenRouter): просит пользоваться ВСЕМ набором markdown — `##`/`###`-заголовки
  разделов, **блок-цитаты `>` для речи/готовых фраз** (хук, реплика в кадр, пример), жирный
  на ключевом, списки, таблицы для сравнений, `---` между крупными частями — как это круто
  делал Claude. Всё это стилизовано рендерером (Mantine `TypographyStylesProvider` в
  `components/Chat/Markdown.tsx`), поэтому цитаты/заголовки отображаются красиво. С оговоркой
  «разметка оформляет, а не заменяет мысль; заголовки/цитаты — где реально раздел/реплика;
  это по-прежнему живая речь от первого лица с матом к месту, а не сухая презентация». **Добавляется только на
  тематических/разборных запросах** (`route.category !== "chat"`, как и `OUTPUT_DISCIPLINE`):
  болтовню (приветствия, «как меня зовут», спасибо → `category === "chat"`) разметкой не
  раздуваем. Claude-стратегию и общий промпт не трогает; ответы рендерятся как markdown
  (`components/Chat/Markdown.tsx`).
- 🟢 **Языковой гвард GLM (чистый русский).** GLM — китайская модель, на длинной русской
  генерации протекает чужими токенами: иероглифы (`泅` вместо «плаваешь»), латиница
  вперемешку с кириллицей («stepнёшь», «Named», «vending», «Roulette»), кальки (kit→«кит»),
  опечатки авто-подстановки («Кловна»). Claude этим не страдает. Решение — константа
  `GLM_LANGUAGE` в `glm.ts`, дописывается в КОНЕЦ system-месседжа **на ВСЕ ответы GLM**
  (в т.ч. `chat`, в отличие от `MARKDOWN_FORMATTING`): требует писать только кириллицей, целыми
  русскими словами, заменять всплывшие иностранные токены русским эквивалентом; латиница —
  только в общепринятых терминах (YouTube/reels/CTA) целым словом; капс для акцента в хуках
  разрешён. **Явно разведено с голосом Велижанина** (чтобы не поймать коллизию «чистый
  русский» ↔ «говори как я»): правило — про происхождение слов (русские, целые), НЕ про
  вежливость/литературность; мат, сленг, рубленые фразы сохраняются как в блоке «Мой
  голос». ⚠️ Промптом проблема **сокращается, но не лечится полностью** — это слабость
  самой модели; для чистого русского Claude надёжнее.
- 🟢 **Скрытый авто-ретрай GLM при перегрузе (concurrency Z.ai).** `glmStrategy.stream`
  оборачивает открытие+чтение стрима в retry-цикл: при `429` (упёрлись в лимит
  одновременных запросов Z.ai), `5xx`/`408`, сетевом сбое или обрыве **до первого
  токена** — повторяет до `GLM_MAX_RETRIES` раз (env, дефолт 3) с экспоненциальной
  паузой+джиттером (`glmBackoffMs`: ~0.6→1.2→2.4с, кап 4с; уважает `Retry-After`).
  **Таймаут попытки (`GLM_TIMEOUT_MS`, env, дефолт 40с) через `AbortController`:** рвёт
  зависший запрос, если не пришёл ОТВЕТ (первый байт) или очередной ЧАНК стрима за это
  время (таймер взводится перед `fetch`, перевзводится после заголовков и на каждый
  чанк). Без него `fetch` на мёртвом соединении Z.ai висел бесконечно — пользователь
  ловил «вечный ретрай» (бэкофф-то короткий, а само сетевое ожидание ничем не
  ограничивалось). По таймауту до первого токена — уходим в следующий ретрай; после
  первого токена — обрываем с понятной ошибкой (залипший стрим лучше оборвать, чем висеть).
  Ретрай **невидим** — пока пользователю не отдан ни один токен, он видит только
  индикатор загрузки, а `: ping` из `route.ts` держит SSE живым. Как только пошёл
  текст (`firstTokenAt`) — обрыв уже НЕ прячем (нельзя переписать показанное),
  пробрасываем ошибку. Роутер (`router.ts`) к перегрузу устойчив отдельно — его
  `try/catch` откатывается на keyword-эвристику. Задел под нагрузку ~50–100
  одновременных юзеров на одном GLM-аккаунте.
- 🟢 **Выбор движка — глобальный, в админке (не пользовательский).** Тумблер Claude/GLM
  у пользователя в шапке чата **убран**. Теперь движок — глобальная настройка
  `AppSettings.provider` (`AppSetting` key `provider`, дефолт `claude`, см. `src/lib/settings.ts`),
  правится в админке (`/admin` → карточка «Движок модели», `SegmentedControl`; валидируется
  в `PATCH /api/admin/settings`). Применяется ко ВСЕМ юзерам: `POST /api/chat` берёт
  `settings.provider` (тело запроса больше не несёт `provider`); `store/settingsSlice` поле
  `provider`/`setProvider` удалены.
- 🟢 **OpenRouter — третий провайдер + выбор модели + режим промпта.** `LlmProvider`
  теперь `claude|glm|openrouter`. Стратегия `src/lib/llm/openrouter.ts` (OpenAI-совместимый
  стрим с ретраями/таймаутом как у GLM; ключ `OPENROUTER_API_KEY`, модель из
  `settings.openrouterModel`, приходит в `StreamArgs.model`; usage/cost из финального чанка).
  В админке (`/admin/flags` → «Движок модели») при выборе **OpenRouter** появляются:
  **селектор модели** (каталог тянется из `GET /api/admin/openrouter/models` → публичный
  `openrouter.ai/api/v1/models`, ~340 моделей, searchable) и **режим промпта**
  (`AppSettings.routing`): `smart` — наш BM25-роутинг знаний; `full` — отдаём ВСЮ базу
  целиком (`buildFullSystem` в `src/lib/llm/system.ts`: книга+оба TG+YouTube-транскрипты+
  форматы+контент-план, ~207К+ токенов, одна кэш-точка на хвосте), БЕЗ вызова LLM-роутера (`fullModeRoute` в
  `router.ts` — все флаги on, категория дешёвой эвристикой). Full-режим — под модели с
  кэшированием контекста (DeepSeek): «дорогой» объём платится раз, дальше из кэша. Применяется
  и к `/api/chat`, и к ИИ-разбору видео. Новые ключи `AppSetting`: `openrouter_model`, `routing`.
  - **Фикс «lost in the middle» в full-режиме (`FINAL_CHECKLIST` в `system.ts`).** В full
    между антипаттернами (начало) и вопросом (конец) лежит ~207К токенов всей базы — конкретные
    правила «тонут в середине»: модель их помнит (если прямо спросить «что забыл?» — честно
    признаётся), но перестаёт применять (гэп «знаю/делаю»). Пример сбоя: точка в середине
    названия ролика (Антипаттерн №4), хотя правило чёткое. Лечим recency-рычагом (тем же, что
    у smart-режима, где ретрив идёт в конце): `buildFullSystem` добавляет ПОСЛЕДНИМ system-блоком,
    вплотную к вопросу, спрессованную самопроверку — по одной строке на каждый жёсткий
    антипаттерн/правило роли, с рамкой «прогони ответ по списку перед отправкой, приоритет за
    ним». Это НЕ новые правила, а повтор существующих на сильной позиции (~400 токенов,
    некэшируемый — хвост и так пер-юзерный). Новое правило, которое модель дропает, — добавлять
    сюда одной строкой (единственная точка «подъёма» правил на recency). Только full-режим;
    у smart хвост занят ретривом (блоки «копируй дословно»), его не трогаем.
  - **Recency-слой методики в full-режиме** ([src/lib/llm/method-digest.ts](src/lib/llm/method-digest.ts)) —
    чек-лист выше закрывает ЗАПРЕТЫ, но модель ещё и не применяла саму методику (писала из
    дефолтного распределения, не по ВИСП/Ханту). Три статичных блока в `buildFullSystem`
    СРАЗУ ПОСЛЕ дампов базы (recency): **`KNOWLEDGE_MAP`** — карта «задача → слой/раздел базы»
    (модель идёт за дословными формулировками в нужное место 207К, а не отвечает по памяти);
    **`METHOD_DIGEST`** — конспект рабочих алгоритмов (позитивный слой: ВИСП + 3 эмоции,
    лестница Ханта, структура лонга, CTA-раскладка, удержание, шортсы, контент-план) +
    **пре-флайт** («перед артефактом молча выбери: формат → ВИСП/эмоция → Хант → CTA/удержание»,
    продублирован строкой в `FINAL_CHECKLIST`); **`GOLD_EXAMPLES`** — два целых эталонных
    ответа (7 названий по ВИСП; сценарий рилса по формату «Самый худший…») — модель копирует
    примеры лучше, чем выполняет правила. Все три статичны и кэшируются; **кэш-точка Claude
    перенесена с книги на `GOLD_EXAMPLES`** (последний статичный блок — кэшируется весь префикс).
    Итого ~4К токенов. Дропает конкретный инструмент методики → дописывать в `METHOD_DIGEST`;
    новый слой базы → строка в `KNOWLEDGE_MAP`.
    **Методика — молча:** юзер терминов не знает и хочет сразу готовый вариант, поэтому
    ВИСП/Хант/«печёночный торт» наружу НЕ выносятся — комментарий к артефакту по-человечески
    («тут кликают на страх потерять деньги»), термины — только если юзер сам ими оперирует
    или спросил «почему». Зашито в `METHOD_DIGEST` («Методика работает МОЛЧА»), `FINAL_CHECKLIST`
    и Антипаттерн №3 (его «КАК НАДО» раньше само поощряло «называй буквы ВИСП» — переписано).
  - **Параметры генерации OpenRouter (`AppSettings.openrouterParams`).** Под выбранной
    моделью в `/admin/flags` — блок «Параметры генерации»: крутилки temperature / top_p /
    top_k / min_p / top_a / frequency·presence·repetition_penalty / max_tokens / seed +
    селектор **Reasoning (thinking)** (low/medium/high, «выкл» = не передаём). Показываются
    ТОЛЬКО те, что модель заявляет в `supported_parameters` (каталог `GET /api/admin/
    openrouter/models` теперь отдаёт `supportedParams` на модель). Реестр параметров +
    нормализация (белый список ключей, зажим диапазонов) + сборка тела запроса — чистый
    модуль [src/lib/llm/openrouter-params.ts](src/lib/llm/openrouter-params.ts)
    (`OpenRouterParams`, `OR_NUMERIC_PARAMS`, `normalizeOpenRouterParams`,
    `buildOrRequestParams`; reasoning → `reasoning: { effort }`). Заданные значения хранятся
    в `AppSetting` (`openrouter_params`), приходят в стратегию через `StreamArgs.orParams` и
    подмешиваются в тело запроса (перекрывают дефолты, напр. `max_tokens`; незаданные не шлём,
    неподдерживаемое OpenRouter игнорирует сам). Claude/GLM `orParams` игнорируют. **Thinking
    у OpenRouter управляется ТОЛЬКО отсюда** (в отличие от Claude, где adaptive-thinking
    зашит в стратегию по `route.category`) — по умолчанию reasoning выключен.
  - **Пин провайдера (`AppSettings.openrouterProvider`) — ключ к кэшу.** OpenRouter по
    умолчанию БАЛАНСИРУЕТ запросы между ~16 аптсрим-провайдерами модели (в логах видно:
    SiliconFlow → Alibaba → GMICloud → …). Кэш DeepSeek **пер-провайдерный**, поэтому при
    балансировке cache hit rate = 0% (каждый запрос на другом провайдере = промах), а цена
    скачет (у каждого провайдера свой прайс). Настройка «Провайдер (пин для кэша)» в
    `/admin/flags` шлёт `provider: { order: [slug], allow_fallbacks: true }` — приоритет
    одному провайдеру (кэш греется, пока он жив), но с ФОЛБЭКОМ на других при его
    сбое/недоступности/отключении политикой данных (иначе весь чат падал с `404 "No
    endpoints found"` / `429`; ценой холодного кэша на время сбоя). Список провайдеров
    модели тянется из `GET /api/admin/
    openrouter/providers?model=` (проксирует `…/models/{author}/{slug}/endpoints`), показывает
    цену входа/кэша + `supports_implicit_caching` (✓), сортирует кэш-провайдеров вверх. slug
    для routing = префикс `tag` («deepinfra/fp4» → «deepinfra»). Для full-режима на DeepSeek
    оптимален пин на официальный **deepseek** (cache read ~$0.0028/M против $0.14/M входа —
    после первого запроса стабильный ~200К-префикс почти бесплатен). "" = авто-балансировка.
    Прокидывается через `StreamArgs.orProvider`; Claude/GLM игнорируют. Ключ `AppSetting`:
    `openrouter_provider`.
- 🟢 **Заголовок проекта = название канала из брифа** (`brief.channel` || «Новый проект»),
  ставится при создании проекта. Summary-заголовок от нейронки УБРАН: `POST /api/title` и
  `src/lib/llm/title.ts` удалены, авто-заголовок по первому сообщению в `chatSlice.addMessage`
  убран. Переименовать проект можно вручную (шапка проекта → карандаш).

## Переменные окружения
`ANTHROPIC_API_KEY`, `POSTGRES_URL`, `NEXT_PUBLIC_APP_URL`.
Аналитика: `NEXT_PUBLIC_YM_ID` (опц.) — номер счётчика Яндекс.Метрики; без него счётчик
не подключается. **Инлайнится на сборке** — на проде (Docker) переменная должна быть в
окружении BUILD-стадии (иначе в бандл попадёт undefined), см. грабли `NEXT_PUBLIC_*`.
Админка: `ADMIN_BOOTSTRAP_EMAILS` (опц., через запятую) — эти почты считаются админами
без `role` в БД, для разового бутстрапа; альтернатива — `node scripts/make-admin.mjs <email>`.
Оплата (ТБанк): `TBANK_TERMINAL_KEY`, `TBANK_PASSWORD` (секрет терминала) — обязательны для
оплаты; без них кнопка отдаёт «Оплата временно недоступна». `TBANK_API_URL` (дефолт
`https://securepay.tinkoff.ru/v2`), `TBANK_TAXATION` (дефолт `usn_income`), `TBANK_VAT`
(дефолт `none`), `TBANK_FFD_VERSION` (опц.) — для чека 54-ФЗ. `NEXT_PUBLIC_APP_URL` нужен
для `NotificationURL`/`SuccessURL`/`FailURL` (в ТБанк-кабинете укажи тот же домен).
Оплата зарубежными картами (CloudPayments): `NEXT_PUBLIC_CLOUDPAYMENTS_PUBLIC_ID` (публичный
id — клиент, для виджета; **инлайнится на сборке**) и `CLOUDPAYMENTS_API_SECRET` (API-пароль —
сервер: HMAC вебхука + вызовы API). Без них способ «Зарубежная карта» задизейблен. Опц.
`CLOUDPAYMENTS_API_URL` (дефолт `https://api.cloudpayments.ru`). В кабинете CloudPayments укажи
Pay-вебхук на `{NEXT_PUBLIC_APP_URL}/api/payments/cloudpayments/webhook`.
GLM: `GLM_API_KEY` (обязателен для движка GLM), `GLM_MODEL` (дефолт `glm-5.2`),
`GLM_BASE_URL` (дефолт `https://api.z.ai/api/paas/v4`; для bigmodel.cn —
`https://open.bigmodel.cn/api/paas/v4`). Без `GLM_API_KEY` выбор GLM отдаёт ошибку,
Claude работает как раньше. Тарифы GLM захардкожены в `glm.ts` (как у Opus в `claude.ts`).
`GLM_MAX_RETRIES` (дефолт 3) — число невидимых ретраев до первого токена; `GLM_TIMEOUT_MS`
(дефолт 40000) — таймаут ожидания ответа/следующего чанка на попытку (защита от зависшего
соединения Z.ai).
OpenRouter (третий движок): `OPENROUTER_API_KEY` — обязателен для выбора OpenRouter в админке.
`OPENROUTER_MODEL` (дефолт `deepseek/deepseek-chat`) — модель по умолчанию, если в админке не
выбрана. `OPENROUTER_BASE_URL` (дефолт `https://openrouter.ai/api/v1`), `OPENROUTER_MAX_RETRIES`
(3), `OPENROUTER_TIMEOUT_MS` (60000). Модель и режим промпта (умный роутинг / полный промпт)
правятся в `/admin/flags`. Каталог моделей `GET /api/admin/openrouter/models` работает и без
ключа (публичный список), но сами запросы к модели — только с ключом.
Генератор превью: тот же `OPENROUTER_API_KEY` (превью всегда идут в OpenRouter, независимо от
движка чата). `OPENROUTER_IMAGE_MODEL` (дефолт `google/gemini-3-pro-image`, Nano Banana Pro) —
модель по умолчанию, если в админке не выбрана; `OPENROUTER_IMAGE_TIMEOUT_MS` (180000) — картинка
рисуется дольше текста. `UPLOAD_DIR` — куда писать референсы и результаты (дефолт `./data/uploads`;
в Docker задан в compose как `/app/data/uploads` и примонтирован к `./data/uploads` на хосте,
которую при первом деплое надо создать и отдать uid 1001).
YouTube (интеграция канала): `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — OAuth-приложение
из Google Cloud Console. Нужно включить **YouTube Data API v3** и **YouTube Analytics API**,
на consent screen добавить scopes `youtube.readonly` + `yt-analytics.readonly`, а в OAuth
client (тип Web) прописать Authorized redirect URI = `{NEXT_PUBLIC_APP_URL}/api/integrations/
youtube/callback`. Без ключей кнопка «Подключить» в настройках неактивна («интеграция не
настроена»), остальное приложение работает как обычно.
Конкуренты в нише (поиск по YouTube): `YOUTUBE_API_KEYS` — API-ключи Data API **через
запятую**, пул с ротацией. ⚠️ Ключи должны быть из РАЗНЫХ Google Cloud проектов: квота
считается на проект, и пять ключей одного проекта дадут те же 10 000 units, а не 50 000.
В проекте нужен включённый **YouTube Data API v3**; OAuth тут не участвует — данные
публичные. Без переменной раздел показывает «поиск не настроен», остальное работает как
обычно. Опц. `YOUTUBE_API_KEY_DAILY_UNITS` (дефолт 10000) — суточный бюджет одного ключа,
после которого пул сам переключается на следующий (понижать имеет смысл, если тем же
проектом пользуется что-то ещё). Поддерживается и одиночный `YOUTUBE_API_KEY` — как
фолбэк, если ключ один.
Техподдержка (уведомления о вопросах) + уведомления об оплате: `TELEGRAM_BOT_TOKEN`
(от @BotFather) и `TELEGRAM_CHAT_ID` (куда слать — личка админа или группа; у группы id
отрицательный, бота надо ДОБАВИТЬ в неё, иначе Bot API отвечает `chat not found`).
Без них чат поддержки работает как обычно, уведомление просто не уходит (пишется
предупреждение в лог сервера). Бот односторонний — отвечают в `/admin/support`.
Опц. `TELEGRAM_API_BASE` (дефолт `https://api.telegram.org`) — свой прокси Bot API, если
официальный домен с сервера недоступен. На нашем Caddy-прокси Telegram висит на пути
**`/tg`** (`handle_path /tg/*` → `api.telegram.org` с `header_up Host`), т.е. значение —
`https://<PROXY_DOMAIN>/tg`. ⚠️ Прокси пускает только с IP прод-сервера (`remote_ip` в
Caddyfile), поэтому ЛОКАЛЬНО переменную не задаём — иначе 403 вместо отправки.
